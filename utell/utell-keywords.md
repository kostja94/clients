## 2. 术语与搜索意图：Accent 相关词簇

**背景**：**accent modification**、**accent reduction**、**accent neutralization**（正确拼写为 neutralization，非 neutralisition）与 **accent conversion** 在英语里**不完全是同一套搜索意图**；落地页与文案可据此分桶。

### 2.1 教学 / 职业语境（人练发音、清晰度）

| 术语 | 含义与语气 | SEO 备注 |
|------|------------|----------|
| **Accent modification** | 言语病理/教学领域常用首选词：自愿为**提高清晰度**而调整发音，强调**可懂度**，而非抹掉文化身份。 | 与 *reduction* 在多数课程场景下**意图高度重叠**；专业表述更偏 modification。参考：[ASHA — Accent Modification](https://www.asha.org/practice-portal/professional-issues/accent-modification) |
| **Accent reduction** | 历史常见说法，与「缩小与听者习惯的差异、提高沟通」常指同一件事。 | 「reduction」易被误解为「口音有问题」；部分机构改用 modification。参考：[Wikipedia — Accent reduction](https://en.wikipedia.org/wiki/Accent_reduction) |
| **Accent neutralization** | 更偏**向标准化/「中性」目标口音靠拢**，企业呼叫中心、客服培训等语境更常见；相对更「彻底、统一」。 | 与 modification/reduction **有交集**，但用户可能期望**更强「标准化」**；可单独做 FAQ 或子主题。参考：[Accent reduction vs neutralization 讨论示例](https://henrywiles.com/accent-reduction-vs-accent-neutralization-whats-the-difference/) |

**小结**：**modification ≈ reduction** 可作为**同一意图簇**铺词；**neutralization** 单独观察 SERP 与转化，避免与「只提高清晰度」混为一谈。

### 2.2 技术语境：Accent conversion

| 术语 | 含义 | 与前三者的关系 |
|------|------|------------------|
| **Accent conversion** | 语音处理方向：将语音从一种口音**转换**为另一种，常保留**语义内容**与**说话人身份**；用于 CAPT、配音、ASR、实时通信等。 | **与「人学习发音」的营销词不同层级**；搜 conversion 的用户可能更偏**工具/论文/技术**。参考：[IGI Dictionary — Accent Conversion (CAPT)](https://www.igi-global.com/dictionary/accent-conversion-in-computer-assisted-pronunciation-training-capt/95952) |

### 2.3 Utell 关键词策略（执行摘要）

| 动作 | 说明 |
|------|------|
| **同簇合并** | *accent modification*、*accent reduction* 可与现有 *accent reduction software*、清晰度类文案**共用内容矩阵**，title/meta 中可自然覆盖变体。 |
| **neutralization 单独看数** | 在 GSC / 关键词工具中单独看展示与点击；若 SERP 偏 B2B 客服培训，可指向 `/call-center` 或专用 FAQ。 |
| **conversion 勿强行与前三者并成一条意图** | 产品若同时提供 **AI 实时变口音 + 练发音**，可在同一页用不同 H2 区分；否则 *accent conversion* 保持与 **/accent-conversion**、技术向描述对齐，避免与纯「口语课」SERP 错配。 |

## 3. 品牌「Utell」与关键词共现：On-page 放置

目标：让 **Utell** 与目标关键词在**同一结果/同一页面**内稳定共现，利于品牌检索与主题相关性；避免堆砌。

| 位置 | 作用 | 建议 |
|------|------|------|
| **Title（SERP 标题）** | 主题与品牌强绑定 | 全站统一一种模式：**{核心短语} \| Utell AI** 或 **Utell AI — {核心短语}**。每条重要落地页 1 个主意图 + 品牌即可。 |
| **Meta description** | 摘要内再带品牌与 1～2 个变体 | 首句或末句点明 Utell；自然包含 *real-time*、*accent*、*meetings* 等，不必塞进所有同义词。 |
| **H1** | 页面主意图 | 以用户问题为主（如 Real-time accent conversion）；品牌可放在首段或副标题，不必强行 **H1 = Utell**（除非品牌campaign）。 |
| **首屏首段** | 前约 100～150 词内 | *Utell AI* 与核心能力词各出现至少一次，语句自然。 |
| **H2 / FAQ** | 覆盖 **modification / reduction / neutralization** 等长尾 | 用问答式标题，如 *Is Utell for accent reduction or modification?*，正文简短区分并收口到产品。 |
| **内链锚文本** | 从博客链向功能页 | 优先 *Utell accent conversion*、*real-time accent filter with Utell*，少用「click here」。 |
| **结构化数据** | Organization / SoftwareApplication | `name`、`description` 中含 Utell 与一句产品定位（若站点已上 Schema）。 |

**分工**：**首页**承担品牌 + 核心词；**`/accent-conversion`** 作为**词簇枢纽**（conversion、reduction、modification 在 Title/Meta/H2/FAQ 分配）；**各 Use Case 页**用 **Utell + 场景词** 差异化 Title，避免全站重复；**neutralization** 若 SERP 偏 B2B，放在 `/call-center` 或 FAQ。**不必**每个词都塞进同一 Title。

## 6. 平台场景与 SEO 关键词范式

> **平台清单与官网主文案**（各板块英文描述、每条 CTA 文案）见 [utell-platforms.md](./utell-platforms.md)。本节只解决：**按场景选哪类关键词、为什么、与 Utell 能力如何对齐**。

### 6.0 市场简要（关键词视角）

| 场景类型 | 检索与品类观察 | 对 Utell 的启示 |
|----------|----------------|-----------------|
| **视频会议** | 用户心智偏 *meeting*；*AI meeting assistant* 被 [Otter.ai](https://otter.ai/)、[Fireflies.ai](https://fireflies.ai/) 及大量榜单内容占据（例：[AI:PRODUCTIVITY 综述](https://aiproductivity.ai/blog/best-ai-meeting-assistant-2026/)、[Superprompt 盘点](https://superprompt.com/blog/14-best-ai-meeting-assistant-tools-that-actually-save-time-2025)） | 可把 **`AI Meeting Assistant for [平台]`** 作扩展词簇，但与 **accent / voice clarity / live translation** 组合，避免与纯纪要型产品同质化 |
| **即时通讯** | 多为 *WhatsApp call translation*、*real-time translator*、*live captions*（例：[JotMe](https://www.jotme.io/blog/translate-whatsapp-calls)、[Utell WhatsApp use case](https://utell.ai/use-case/real-time-whatsapp-translator/)、[Akkadu](https://akkadu.ai/blog/translate-whatsapp-calls-ai-live-captions/)） | 用 **`AI Translator for [平台] Calls`**，**Calls** 排除纯文字翻译意图 |
| **游戏 / 语音聊天** | *Discord voice*、*noise cancellation*、*voice enhancement* 等 | 避免 *meeting*，用 **§6.4** 范式 |
| **直播 / OBS** | YouTube 偏 *streaming*；OBS 偏 *audio filter*、*plugin* | **§6.5** 拆分 Streaming vs Audio |

### 6.1 视频会议类（Google Meet、Zoom、Teams、Webex、Skype）

**推荐范式**：`AI Meeting Assistant for [平台名]`  
**变体示例**：`AI meeting assistant for Zoom`、`Google Meet AI assistant`（以 GKP/Ahrefs 为准）。

| 要点 | 说明 |
|------|------|
| **场景匹配** | 核心场景是**会议 / 通话**，用户自然使用 *meeting*、*call*、*conference*。 |
| **品类流量** | *AI meeting assistant* 需求体量大、对比内容多；可借势但需差异化着陆。 |
| **意图** | *Zoom AI assistant* / *Google Meet assistant* 多指向会中辅助（听清、翻译、记录等）。 |

**与官网文案**：现多用 *voice clarity / enhancement / accent conversion*（见 [utell-platforms.md](./utell-platforms.md)）；Title/Meta 可 **A/B**：范式句 vs 现用短语，用 GSC 与转化择优。

### 6.2 即时通讯类（WhatsApp、Viber、LINE、Messenger、Telegram）

**推荐范式**：`AI Translator for [平台名] Calls`

| 要点 | 说明 |
|------|------|
| **为何不用 Meeting Assistant** | 用户很少说「在 WhatsApp 上开会」；场景是私聊/跨境通话；痛点是**语言障碍**而非纪要效率。 |
| **为何加 Calls** | *WhatsApp translator* 常指向**文字**翻译；**Calls** 锁定**实时语音**链路，与 Utell 一致。 |

### 6.3 Slack（单独）

**推荐范式**：`AI Voice Assistant for Slack`

| 要点 | 说明 |
|------|------|
| **为何单独** | 非典型会议室；**Huddles / 语音** 多；检索常含 *Slack voice*、*Slack huddle*、*Slack AI*。 |
| **能力表述** | *Voice Assistant* 强调语音侧增强（清晰、口音、降噪），与产品对齐。 |

### 6.4 游戏类（Discord、Steam、Roblox、TeamSpeak、Twitch）

**推荐范式**：`AI Voice Assistant for [平台名]`

| 要点 | 说明 |
|------|------|
| **为何不用 Meeting Assistant** | 场景为 **voice chat**，非开会；*meeting* 易误触、高跳出。 |
| **为何用 Voice Assistant** | 匹配「队友听清、低延迟、降噪/口音」等意图。 |

### 6.5 直播 / 流媒体（YouTube、OBS Studio）

| 平台 | 推荐范式 | 说明 |
|------|----------|------|
| **YouTube** | `AI Streaming Assistant for YouTube` | 意图偏 *streaming*、*live*、创作工作流 |
| **OBS Studio** | `AI Audio Assistant for OBS Studio` | 意图偏 *audio filter*、*noise cancellation*、*plugin* |

| 平台（参见 [utell-platforms.md](./utell-platforms.md) §六） | 推荐 SEO 范式 |
