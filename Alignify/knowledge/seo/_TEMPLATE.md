# 知识块模板 · SEO 专册结构参考

本模板从 `knowledge/seo/` 中 7 篇完整文档归纳而来，并参照 `knowledge/tools/_TEMPLATE.md` 的方法论框架做适配。各节按出现频率排序；**并非每个文档都必须含所有项目**，但覆盖越全，读者越容易在 SEO 主题簇内跨文档对照。

**注**：本模板为 Alignify 知识库内部写作工具，**非**面向读者的输出页面。

> **使用前必读**：方法论硬约束见 [`../README.md`](../README.md) 第一章；当前 slug 对应关系与缺口跟踪见 [`README.md`](./README.md)。

---

## 模板大纲

```
H1 # {主题} · 知识块（非线性笔记）

【元数据块】
1. 材料范围（含整理日期）        ← 必需

2. 规范对照（链到 content/sections/ / technical/） ← 必需

3. 站内文章对照（Alignify SEO 页链接） ← slug 已上线时必需

4. 本分册说明（链 seo/README.md） ← 必需

5. 【可选】与相邻 slug 分流表   ← 涉及 2+ 个易混主题时推荐

6. 以下条目可任意顺序阅读；不是文章体例

【核心概念块】
7. 词汇锚点（加粗术语定义）       ← 必需

8. 专题对照 / 扩展定义（对比表格）  ← 有易混相邻主题或业内二分法时强烈推荐

9. 问题域（为何关注这个主题）    ← 必需

10. 能力栈（概念拆分，非工具功能表） ← 强烈推荐

11. 形态谱系（与具体产品解耦）     ← 强烈推荐

12. 风险 · 合规 · {诚信/治理/…}   ← 必需

13. 落地碎片（实践建议）          ← 强烈推荐

【工具与索引块】
14. 工具与产品类型（品类表格）     ← 强烈推荐

15. 外链索引（URL 列表 + 对比与测评）← 必需

16. 延伸阅读与参考材料           ← 强烈推荐
```

## 与 Tools 模板的关键差异

SEO 知识块**不绑定** `tools-pages-config.ts`，因此元数据块做如下替换：

| Tools 模板 | SEO 模板 | 原因 |
|-----------|----------|------|
| 站内对照（`alignify.co/tools/{slug}`） | 站内文章对照（`alignify.co/seo/{slug}` 或 `/zh/seo/{slug}`） | SEO 页面对应 `/seo/[slug]` 路由 |
| Tools 关键词与 slug 映射 | **删除**；替换为 **本分册说明** | SEO 不在 tools-pages-config 中 |
| （无） | 规范对照（`content/sections/` / `technical/`） | SEO 文章需与站内技术规范、section 写作规范对齐 |

## 各节写作指引

### 1. 材料范围（必需）
格式：
```
**材料范围**：{来源说明}；**未**将 Alignify 站内页面 JSON 当作事实来源复述。网摘整理日期 {YYYY-MM-DD}。
```
示例：
```
**材料范围**：公开网络检索（搜索引擎官方文档、StatCounter/Statista 市场份额数据、行业分析报告与社区讨论摘要）；**未**将 Alignify 站内页面 JSON 当作事实来源复述。网摘整理日期 2026-05-20。
```

### 2. 规范对照（必需）
链到站内技术规范与写作规范。格式：
```
**规范对照**：[section-seo.md](../../section/section-seo.md) · [technical/README.md](../../technical/README.md)
```
若该主题有专门的 section 或 technical 文档，按需增链。至少保留 `section-seo.md` 链。

### 3. 站内文章对照（slug 已上线时必需）
格式：
```
**站内文章对照**：[alignify.co/seo/{slug}](https://alignify.co/seo/{slug})（[中文](https://alignify.co/zh/seo/{slug})） · `content/seo/en|zh/{slug}.json`
```
若 slug 尚未上线，用「待上线 SEO 页时对齐」代替。

### 4. 本分册说明（必需）
固定格式：
```
**本分册说明**：[seo/README.md](./README.md) · 分类：{所属分类，见 README 文件清单}
```
分类选项：入门与学习 / 网站架构与导航 / 技术：抓取、索引与渲染 / On-page 与标记 / 链接：内链、外链与 SERP / 内容与规模化 / 流量、测量与诊断 / 工具盘点。

### 5. 与相邻 slug 分流（可选）
用 markdown 表格列出 slug 与 1-2 个相邻 slug 的差异。SEO 主题簇常见的分流维度：
- 主题焦点（如 `crawler` 侧重爬虫身份与流量形态，`how-search-engine-works` 侧重三阶段原理）
- 读者问题（如 `website-indexing` 侧重收录排查，`sitemap` 侧重提交与发现）
- 落地动作（如 `internal-links` 侧重站内链接策略，`link-building` 侧重外链建设）

### 6. 以下条目可任意顺序阅读
固定写法：
```
以下条目可任意顺序阅读；**不是**文章体例，无「第一章、第二章」叙事线。
```

### 7. 词汇锚点（必需）
加粗每个术语，用中文给出定义，英文术语保留原词。格式：
```
- **{术语}**：{定义}。{必要时补充与易混概念的区分}。
```
SEO 知识块关注**搜索生态内的概念**，与 `docs/glossary/` 的术语表互补而非重复。如果某术语在 glossary 中已有精确定义，可简写并链过去。

### 8. 专题对照 / 扩展定义（推荐）
用于展示 SEO 主题内的关键二分（如「爬取 vs 索引」「Disallow vs noindex」），或与相邻主题的分界。用 markdown 表格。
*参考*：`how-search-engine-works.md` 的三阶段对照表、`crawler.md` 的 Crawl vs Scrape 辨析表。

### 9. 问题域（必需）
无序列表，每条解释一个「为何读者会关注这个 SEO 主题」的根本原因。SEO 问题域常围绕：
- **认知痛点**（用户不懂某概念导致误操作）
- **工具偏差**（不同测量仪器口径不一致）
- **平台差异**（Google/Bing/百度行为不同）
- **时效性**（官方文档与行业实践的版本漂移）

建议每条聚焦一个动力，而非展开流水账。
*参考*：`how-search-engine-works.md` 的 4 条问题域结构清晰、各条不重叠；`learn-seo.md` 的 5 条问题域聚焦学习路径的认知陷阱。

### 10. 能力栈（推荐）
概念拆分解耦，不以单一工具的功能表为导向。SEO 能力栈通常沿「可发现 → 可爬取 → 可索引 → 可呈现 → 可度量」流水线展开，或按「技术 SEO / On-page / 内容策略 / 测量与归因」分层。
*参考*：`how-search-engine-works.md` 的 5 维能力栈沿三阶段流水线展开；`learn-seo.md` 的 6 维能力栈聚焦学习者的技能树。

### 11. 形态谱系（推荐）
与具体产品/品牌解耦的类型划分。SEO 形态谱系常围绕：
- **搜索引擎侧**：经典三阶段模型、AI 摘要层、垂直子系统
- **站长侧**：官方工具链（GSC/Bing Webmaster）、第三方审计工具、日志与爬虫
- **内容侧**：信息型/交易型/导航型页面各自的技术与内容策略

每条描述一类形态的核心特征，而非罗列产品名。
*参考*：`how-search-engine-works.md` 的 3 型谱系（经典三阶段、质量安全闸、垂直子系统）。

### 12. 风险 · 合规 · {后缀}（必需）
固定前缀 `风险 · 合规 · `，后缀根据主题定制：
- **技术 SEO** → `治理（外部框架可对照，非法律意见）`
- **内容与策略** → `诚信（外部框架可对照，非法律意见）`
- **流量与测量** → `隐私（外部框架可对照，非法律意见）`

内容覆盖方向：
- 付费 ≠ 自然排名提升
- 黑帽与操纵风险
- 数据合规（GDPR、中国网络安全法等）
- 平台政策变更风险
- 测量工具的局限性

### 13. 落地碎片（推荐）
实操导向的无序列表，每条是一个可操作的行动建议。SEO 落地碎片应避免写成「教程步骤」，而是**决策启发**——在什么情境下优先做什么。

### 14. 工具与产品类型（推荐）
Markdown 表格列出检索词常混在一起的品类。SEO 工具品类表的列：
```
| 类型（英文常检索词） | 典型包含什么 | 备注 |
```
与 `best-tools.md` 的分工：`best-tools.md` 是 SEO 工具谱系总览，各主题知识块的「工具与产品类型」表聚焦**该主题领域内**特有的品类混用问题。

### 15. 外链索引（必需）
URL 列表 + 对比与测评。URL 表格式：
```
| 名称 | 一句话 | URL |
```
后接 `### 对比与测评（第三方；观点非官方）` 小节，汇总社区与媒体常见观点。

**参考来源质量标准**：与 tools 模板 §14a 完全一致（学术论文、市场报告、官方文档、知名科技媒体；拒绝论坛、中文技术社区、个人博客、营销落地页）。详见 [`../tools/_TEMPLATE.md`](../tools/_TEMPLATE.md) §14a。

### 16. 延伸阅读与参考材料（推荐）
按分类列出站外资源。SEO 延伸阅读的推荐分类：
- 官方文档（Google Search Central、Bing Webmaster Guidelines 等）
- 行业报告（Statista、Gartner、Moz/Search Engine Journal 年度报告）
- 学术论文（信息检索、搜索偏见、用户行为）
- 社区与行业博客（标注作者身份与时效）

## 创建新 SEO 知识块的操作步骤

> **方法论硬约束**：见 [`../README.md`](../README.md) 第一章——独立来源、不从已有文章取材、增量原则。
> **当前缺口**：见 [`README.md`](./README.md) § 文件清单——30 篇待补充，优先补全「入门与学习」与「技术：抓取、索引与渲染」类。

1. 核对 [`seo/README.md`](./README.md) 文件清单，确认目标 slug 是否存在（若已有占位文件则在其上扩展，而非新建）
2. 从本模板大纲复制结构，按 SEO 主题簇特点填充各块
3. 先写**必需**项（材料范围、规范对照、本分册说明、词汇锚点、问题域、风险合规、外链）
4. 再补**推荐**项（站内文章对照、能力栈、谱系、落地碎片、产品类型表）
5. 最后加**可选**项（分流表、对照表、延伸阅读）
6. 如主题涉及多引擎对比（如 search-engine、crawler），确保外链覆盖 Google/Bing/百度/Yandex 等多源
7. 如有重大行业事件（如 Google AI Mode 发布、Bing Copilot 重大更新），考虑是否增加行业注记块
