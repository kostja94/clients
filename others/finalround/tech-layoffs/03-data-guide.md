## 1. 数据源优先级

从上到下，越靠前越权威。**两个独立来源交叉验证后才能上页面。**

| 优先级 | 来源 | 网址 | 可信度 | 适用场景 |
|--------|------|------|--------|----------|
| **P0** | Layoffs.fyi | https://layoffs.fyi/ | ⭐⭐⭐⭐⭐ | 科技行业裁员的第一手追踪，所有公司数据的基准 |
| **P0** | 公司官方声明 | SEC 8-K 文件、官方 Blog、新闻稿 | ⭐⭐⭐⭐⭐ | 裁员规模、原因、时间线的最权威来源 |
| **P1** | TrueUp | https://www.trueup.io/layoffs | ⭐⭐⭐⭐ | 交叉验证 Layoffs.fyi 数据，发现遗漏 |
| **P1** | 权威财经媒体 | Reuters、Bloomberg、WSJ、TechCrunch | ⭐⭐⭐⭐ | 原因分析、背景信息、受影响部门细节 |
| **P2** | Glassdoor / Blind | glassdoor.com、teamblind.com | ⭐⭐⭐ | 员工视角的遣散方案、实际影响范围 |
| **P2** | Levels.fyi | levels.fyi | ⭐⭐⭐⭐ | 薪资数据（如受影响岗位的薪资范围） |
| **P3** | 其他追踪器 | Comprehensive.io、SkillSyncer | ⭐⭐⭐ | 补充参考，不作为主要数据源 |

## 2. 每个数据字段的获取方式

编写公司详情页时，以下字段需要逐个填：

| 字段 | 从哪里找 | 置信度标注 |
|------|----------|-----------|
| **裁员人数** | Layoffs.fyi（首选）→ 公司官方声明（核实） | 标注来源 + 日期 |
| **占员工总数百分比** | 公司官方声明 > 媒体推算 | 媒体推算标「估计」 |
| **裁员时间** | 公司官方声明（公告日期 + 生效日期） | 精确到月份 |
| **原因** | 公司官方声明（CEO 信 / 新闻稿） | 标注「据官方声明」 |
| **受影响部门** | 媒体报道 > Blind 员工帖子 | 非官方来源标「据报道」 |
| **遣散方案** | 公司官方声明 > 媒体报道 | 标注来源 |
| **重组费用** | SEC 8-K 文件 > 媒体报道 | 精确数字需 SEC 文件核实 |
| **CEO 声明原文** | 公司官方 Blog / 新闻稿 | 直接引用，加引号 |

## 3. 更新频率

| 数据类型 | 更新频率 | 触发条件 |
|----------|----------|----------|
| **宏观 YTD 数据**（总人数、公司数） | 每周 | 每周一或周五刷新 Layoffs.fyi 首页数字 |
| **单家公司页数据** | 事件驱动 | 该公司宣布新一轮裁员时 |
| **行业分布数据** | 每月 | 月初汇总 |
| **来源链接有效性** | 每月 | 逐链检查，替换失效链接 |

## 4. 数据冲突处理

当两个来源的数字不一致时（常见）：

**规则：优先采信更权威的来源；在页面上标注数据差异。**

### 示例

Layoffs.fyi 报 Amazon 裁员 16,000，TrueUp 报 14,500：

```
✅ 正确做法：
"Amazon 在 2026 年 1 月宣布裁员约 16,000 人（来源：Layoffs.fyi），
另有追踪平台估计约 14,500 人（来源：TrueUp）。"
```

```
❌ 错误做法：
"Amazon 裁员 16,000 人。"（只有一个来源，未提差异）
```

### 冲突处理优先级

1. 公司官方数字 > Layoffs.fyi > TrueUp > 媒体报道
2. 当公司官方数字与追踪平台差异 > 20% 时，两个都写，标注来源
3. 当两个媒体来源报道不一致时，优先采用 Reuters / Bloomberg（一级通讯社）

## 5. 引用格式规范

在页面上引用数据时，统一使用以下格式：

### 裁员数据

```
{公司} 在 {时间} 宣布裁员约 {人数} 人，约占员工总数的 {百分比}%
（来源：{来源名称}，{日期}）。
```

### 后续更新

```
{日期} 更新：{公司} 宣布追加裁员 {人数} 人（来源：{来源名称}）。
```

### 免责声明（每页必加）

```
> 数据来源为公开报道与第三方追踪平台，可能与公司实际数字有差异。
> 最新信息以公司官方披露为准。本页面最后更新于 {日期}。
```

## 6. 数据记录规范

在 [data/layoff-data.md](./data/layoff-data.md) 中，每家公司至少记录以下字段：

| 字段 | 示例 | 必填 |
|------|------|------|
| 公司名称 | Amazon | ✅ |
| 裁员规模 | 16,000+ | ✅ |
| 时间 | 2026-01 | ✅ |
| 占比 | ~1% of corporate workforce | 可选 |
| 原因 | 企业岗位优化 | 可选 |
| 来源链接 | https://... | ✅ |
| 最后更新日期 | 2026-06-03 | ✅ |

## 7. 常见错误

| 错误 | 为什么不对 | 正确做法 |
|------|-----------|----------|
| 只有一个来源就写进页面 | 可能不准确，且显得不专业 | 至少两个独立来源交叉验证 |
| 把「计划裁员」写成「已裁员」 | 计划可能调整或取消 | 区分「宣布计划裁员」和「已完成裁员」 |
| 不同公司的裁员数字直接加总对比 | 口径不同（含不含合同工、全球 vs 美国） | 标注统计口径 |
| 用旧数据不更新 | 用户看到过时信息，信任度下降 | 每个数据旁标注「最后更新日期」 |
| 不保留来源链接 | 无法溯源，失去可信度 | 每个数字保留原始 URL |
