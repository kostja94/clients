# Dynal 文档编写规范

> 本文档定义 Dynal 项目内所有 Markdown 文档的编写、格式与维护规范。
> 关联：[dynal-文件夹优化方案.md](./dynal-文件夹优化方案.md)

---

## 一、格式规范

### 文档头部

- **样式引用**：`> 遵循 [dynal-文档编写规范](./dynal-文档编写规范.md)`
- **关联文档**：`> 关联：[doc1](./doc1.md) | [doc2](./doc2.md)`
- **产品入口**（如适用）：`*产品入口*：https://dynal.ai/`
- **状态说明**（如适用）：`> **⚠️ 已停止运营**` 等

### 标题层级

- **H1**：仅用于文档主标题，每文件一个
- **H2**：一级章节（如：产品概览、关键词策略），正文用 `## N. 标题` 编号
- **H3**：二级小节
- **H4**：细分项（慎用）

### 列表

- 无序列表使用 `-`，层级不超过 3 层
- 有序列表用于步骤、优先级

### 表格

列名简洁，内容对齐。示例：

```
| 列名1 | 列名2 | 列名3 |
|-------|-------|-------|
| 内容  | 内容  | 内容  |
```

### 引用块

`>` 用于重要说明、引用、待确认事项。

### 链接格式

- 外部链接：`[显示文字](URL)`
- 内部引用：`[目标文档](./file.md)` 或 `[锚点链接](./file.md#章节)`
- 相对路径优先，避免 `../../` 跳出项目文件夹

### 日期与数字

- 日期格式：YYYY-MM-DD（如 2026-05-11）
- 数字：千位分隔符可选，百分比保留一位小数

## 二、内容原则

### 主题一致性

- **单一主题原则**：一个文档聚焦一个主题；若涉及多主题，拆分为多文档并通过引用关联
- **只保留与当前主题相关的内容**：无关段落、示例、说明应移至对应文档或删除
- **跨主题内容**：若某段内容服务于多个文档，放在最核心的文档中，其他文档仅做引用
- **控制文档职责**：每个文档有清晰职责边界，避免越界堆砌

### 去重与合并

- **合并重复内容**：同一信息出现在多处以一处为准，其他地方改为引用
- **交叉引用替代复制**：能通过链接解决的，不重复粘贴；用「见 [文档名](./path)」指向权威来源
- **定期检查**：在增改内容时顺带检查是否产生新的重复

---

## 三、文档互链

- **相关文档互相引用**：有逻辑关联的文档应在开头或文内注明对方路径
- **引用格式**：使用相对路径链接，如 `[文档名](./path/to/doc.md)`
- **站内关联节**：每份内容文档末尾应列出文件夹内相关文档的完整链接列表，便于跳转

## 四、命名与文件管理

### 命名约定

- 根目录内容文件：`dynal-{英文主题}.md`（如 `dynal-features.md`）
- Blog 文章：`NN-{英文-slug}-2026.md`（如 `01-types-of-linkedin-posts-2026.md`）
- 索引文件：`README.md`

### 文件大小

- 单文件控制在 4KB–15KB 为宜
- 过小（<4KB）考虑是否可合并；过大（>15KB）考虑是否可修剪或拆分

### 拆分建议

当一篇文档难以快速把握结构、存在多个彼此独立的一级主题、或篇幅已影响维护与检索时，应优先考虑拆成多篇单一主题文档，由索引页或文首「关联文档」串起。拆分后必做：在新旧文档间补全双向互链，删除原长文中已迁出段落，改为引用新文档路径。

### 重命名

文件名应反映主题。若正文优化后文件名与真实主题不符，应重命名文件。重命名后必做：全局查找并更新所有引用该路径的相对链接。

## 五、自检清单

| 检查项 | 说明 |
|--------|------|
| 主题一致 | 每段内容是否都服务于文档主题？ |
| 无重复 | 同一信息是否只出现在一处？ |
| 内容聚焦 | 是否存在与当前主题无关的段落？ |
| 互链完整 | 相关文档是否互相引用？末尾是否有站内关联节？ |
| 篇幅合理 | 单篇是否在 4KB–15KB 范围内？是否适合拆分成多篇？ |
| 文件名匹配 | 文件名是否与标题、正文主题一致？ |
| 链接有效 | 重命名或拆分后，仓库内相对路径是否已全部更新？ |
| 格式一致 | H1/H2/H3 层级是否正确？表格、列表是否符合规范？ |
