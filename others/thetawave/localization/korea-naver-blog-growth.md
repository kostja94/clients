## 一、为什么韩国增长要单独配 Naver Blog

| 背景 | 对 ThetaWave 的含义 |
|------|---------------------|
| 在韩国，大量用户用 **Naver 生态** 搜索与消费长文，与「只押 Google 英文站」的打法不同。 | 韩语教育类、工具对比、讲座笔记教程等，适合用 **Naver Blog** 承接长意图、建立信任。 |
| 官网承担 **SSoT（价格、政策、产品真相源）**；Naver 承担 **拉新、韩文教育内容、讨论与社交证明**。 | 博客中关键承诺与官网 **表述一致**；重要条款以官网为准。 |
| 独立站可继续做 **GSC/GA4**；Naver 内数据看 **平台统计**，两套 **不可混读**。 | 增长汇报需分渠道；外链到 thetawave.ai 时统一 **UTM**（见下文章节十）。 |

## 三、如何设置：从 Naver 账号到博客与编辑环境

### 3.1 Naver 账号

- 使用 **可长期由团队或指定负责人运营** 的 Naver ID 注册/登录（ThetaWave 建议 **公司运营专用号**，非员工私人日常号，便于 **权限与 2FA 交接**；见上 **§〇**）。
- 在内部文档中 **登记账号、恢复方式、绑定手机/邮箱**；若注册邮箱为 **@thetawave.ai 或公关联络邮箱**，与对外沟通一致，便于续号与审计。

### 3.2 创建或进入博客

- 在 Naver 内进入 **Blog** 服务，按向导 **开通博客**（若已开通则进入 ** 내 블로그 / 블로그 관리**）。
- 长期发文建议：优先用 **PC 端博客** 或 **Naver 官方博客 App** 的 **스마트에디터 ONE（SmartEditor ONE）** 写长文；社区有信息称 **手机浏览器** 上长文能力可能收缩，**勿依赖手机网页写长稿**（以官方最新说明为准，见 [发布与编辑指南 2.1](../../Naver/Naver-Blog-发布与编辑指南.md#21-它是什么在哪用)）。

### 3.3 编辑台默认设置（第一次发文前必做）

在 **블로그 관리** 内寻找 **기본 정보 관리、기본 에디터 설정、기본 서체/행간** 等（具体路径以界面为准）：

| 设置项 | 建议 |
|--------|------|
| **기본 에디터** | 选 **스마트에디터 ONE**，团队与后续迁移成本最低。 |
| **서체/크기/자간/행간/정렬** | 与品牌可读性一致；长文用清晰正文字体，**行距略大于 1.0** 利手机阅读。 |
| **색상** | 正文高亮 **少而准**；多色易伤可读性。 |

> 把上述一次性设好，避免每篇手调。详见 [发布与编辑指南 二.2](../../Naver/Naver-Blog-发布与编辑指南.md#22-把기본-설정先配好再写推荐)。

### 3.4 分类结构（Category / 카테고리）

- 先规划 **2～3 个主类**，与 ThetaWave 的韩语关键词簇一致（可对照 [feature-pages-keywords-localization.md](../keywords/feature-pages-keywords-localization.md) 里韩国相关检索词，若有 P1/P2 韩语条目）。
- **不要**每篇随意新建冷门小类；系列文章用 **同一主类** 便于内链与读者订阅预期。

## 四、Profile 与「博客层」品牌呈现怎么设

Naver 界面上通常分 **Naver 账号资料** 与 **博客层展示信息**；实务上应统一视为「读者第一眼看到的 profile」。

### 4.1 建议检查项（季度或开号时完整填一次）

- **博客名/ 표시名**：能识别为 ThetaWave 相关官方或授权账号（与公司对外的韩文/英文品牌写法一致，见内部 glossary）。
- **博客简介（소개）**：1～3 句话说明 **谁在用、解决什么问题、与 thetawave.ai 的关系**；避免与官网主叙事矛盾。
- **主视觉/封面（若有）**：与 [thetawave-brand-visual.md](../thetawave-brand-visual.md) 色调与字体层级协调；小屏能辨认 logo 或主色即可。
- **对外链接（若后台提供）**：优先链向 **thetawave.ai 韩语页或主站**（若暂无 `/ko/`，用主站 + UTM，见第十节），避免短链/可疑域。
- **默认开放与互动策略**：与发文策略一致（见第五节「发刊前检查」）；**전체공개、검색 허용** 通常利于发现性，除非内容刻意不对公网。

### 4.2 与「多账号/矩阵」的边界

- 若未来多账号，须避免 **一机多号、互粉互赞、异常频率** 等易触发风控的行为（见 [Naver 总览 五](../../Naver/Naver-Blog.md#五合规与品牌安全) 与 [发布与编辑指南 六](../../Naver/Naver-Blog-发布与编辑指南.md#六多账号矩阵的底线)）。商业矩阵在 **合同与台规** 下运作；公开身份要经得起读者与平台信任审阅。

## 五、第一篇文章怎么选、怎么写、怎么发

### 5.1 首篇主题（务实建议）

- **选「高意图、可独立完成、少争议」** 的单一子问题，例如：  
  - 大学生강의 노트要点的「한 가지 워크플로」教程；或  
  - 「AI 노트 앱」品类里 **1 个明确对比维度**（非攻击竞品，以事实与体验为主）。  
- **避免**首篇就写全功能大全或强促销，利于建立 **C-Rank/垂类** 所讨论的「主垂、原创、稳定」观感（为行业归纳，**非 Naver 官方承诺**，见 [发布与编辑指南 4.3](../../Naver/Naver-Blog-发布与编辑指南.md#43-业经常提及的-c-rankdia-等)）。

### 5.2 正文结构（在 ONE 里完成）

| 块 | 要点 |
|----|------|
| **제목** | 主关键词尽量 **靠前**；一眼说清，忌标题党。 |
| **首段** | 前 2～3 句写清 **结论、适用范围、谁该读**（降低跳出）。 |
| **H2/H3 小标题** | 拆段、利于扫读；与仓库内「Naver 对结构化正文更友好」的编辑惯例一致。 |
| **图/视频** | 原创或授权；控制体积兼顾流量；**대체 텍스트(ALT)** 按界面填写。 |
| **粘贴** | 从网页/Word 粘贴易带脏格式，先 **纯文本** 或 에디터 的纯文本粘贴再排版（见 [发布与编辑指南 2.4](../../Naver/Naver-Blog-发布与编辑指南.md#24-贴文时脏代码)）。 |

发前在 ONE 里切换 **PC·태블릿·모바일 미리보기** 各看一遍。

### 5.3 发刊界面（最容易漏的项）

| 项 | 建议 |
|----|------|
| **카테고리** | 落入已规划主类。 |
| **태그** | 少而精；主词 + 1～2 个同义/长尾，忌堆砌。 |
| **公开范围** | 教学/增长向内容一般用 **전체공개**；**검색 허용** 对可发现性通常应打开。 |
| **댓글 / 공감 / 外部分享** | 按策略一次打开，避免发后发现别人无法 **공감**（见 [发布与编辑指南 3.3](../../Naver/Naver-Blog-发布与编辑指南.md#33-评论공감点赞类外部分享)）。 |
| **代表图/썸네일** | 一图一主题，列表小图也清晰。 |
| **草稿与定时** | **임시저장、예약 발행** 按流程；多设备协作时确认终稿在 ONE 里为同一份。 |

### 5.4 发后行为

- **定稿发**：社区经验认为发后 **频繁小改、反复保存** 可能对展示稳定性不友好；大改可评估新文「업데이트」承接（以平台能力为准），见 [发布与编辑指南 2.5](../../Naver/Naver-Blog-发布与编辑指南.md#25-反复修改)。  
- 若 [Search Advisor](https://searchadvisor.naver.com/) 对 **单篇 URL** 提供 **收录/再抓取** 类入口，可按官方面向博客 URL 的说明操作（与 **独立站** 的 Search Advisor 分清楚对象），见 [Naver 搜索引擎 三](../../Naver/Naver-搜索引擎.md#三search-advisor站长平台)。  
- **24～48 小时**内自然阅读与评论、공감 等健康互动；**禁止** 互刷、机刷（见 [发布与编辑指南 4.2](../../Naver/Naver-Blog-发布与编辑指南.md#42-发前发后建议清单可打印)）。

### 5.5 与官网的链接与 CTA

- 文内 CTA 链向 **thetawave.ai** 时带 UTM，与落地页、广告表述一致。  
- 价格、学生折扣、退款等 **以官网英文/最新政策页面为准**；博客可做摘要但避免过时数字长期不更新。  
- 与 [blog/internal-external-links-checklist.md](../blog/internal-external-links-checklist.md) 的「分层链接、E-E-A-T」精神一致；**Naver 发刊界面不读取** Markdown 的 `frontmatter`，但仓库内仍可用 **[localization/01-thetawave-brand-intro-ko-2026.md](./01-thetawave-brand-intro-ko-2026.md)** 的 YAML（`naver.utm`、`language: ko` 等）作为 **제목·요약·UTM·发刊检查单** 的单点记录，正文粘贴进 ONE 时略去元数据区即可。

### 5.6 附录：「ThetaWave / thetawave」品牌介绍长文——韩文成稿（ONE 编辑台）

> **用途**：在 Naver 上强化 **品牌词**（`ThetaWave` / `thetawave` 等，与 [thetawave.md](../thetawave.md) 拼写一致）的检索落点，与 **thetawave.ai 官网** 分工：官网为 **SSoT**；本文为 **韩文概览 + 场景化入口 + 官方链接**。**未获 Naver「공식 블로그」认证时，勿暗示绿勾式「플랫폼 공식 인증」**（见 **§〇**）。

**成稿位置**：韩文 Naver 品牌介绍放在 **[localization/](./readme.md)**，文件名为 [01-thetawave-brand-intro-ko-2026.md](./01-thetawave-brand-intro-ko-2026.md)（与自站 `blog/` **分目录**，避免与 `/blog` 英文稿混放）。**文体**可参考自站 [01-best-ai-note-takers-2026.md](../blog/01-best-ai-note-takers-2026.md) 的 **信息密度、要点条、H2 块、比较/路由表**。**Naver 发刊** 不读 YAML，但稿内 `title` / `description` / `naver` 块可供复制；下表是 **平台字段 → ONE 行为** 对照。

| 英文站 blog 习惯 | 在 Naver（스마트에디터 ONE）的落地方式 |
|-------------------|----------------------------------------|
| `title` / `description` | **발행** 屏填写 **제목**；**요약/부제** 或首段前 2～3 句承担 SERP/列表摘要信息（以界面是否提供 **부제·요약** 为准）。 |
| 正文 H1 | ONE 中主标题即 **제목**；文内大节用 **소제목（H2）** 按钮，子节用 **H3**（与 **§5.2** 一致）。 |
| `## Key takeaways` 列表 | 文首或第二节用 **「핵심 한눈에」** 等 H2，下列表用 **글머리 기호**；忌从 Word/Web **带格式粘贴**（见 [发布与编辑指南 2.4](../../Naver/Naver-Blog-发布与编辑指南.md#24-贴文时脏代码)）。 |

| 外链、related | 文内 **하이퍼링크** 到 thetawave.ai 子路径；同博客后续文用 **「관련 글」** 段落 + 内链（**§5.2**）。 |
| 主图 `image` | **대표이미지/썸네일** + 正文必要处 **이미지 삽입**；**대체 텍스트(ALT)** 填写（**§5.2**）。 |

**建议 카테고리 / 태그 / 발刊项（发刊前在 발행 屏勾选）**

| 项 | 建议 |
|----|------|
| **카테고리** | 已规划的 **브랜드/제품 소개** 或 **AI 학습 도구** 主类之一（与 **§3.4** 一致，勿临时新建过细类）。 |

| **UTM** | 外链 `https://thetawave.ai/...` 带与负责人约定的参数（**第十节**），如 `utm_source=naver_blog&utm_medium=social&utm_campaign=kr_growth_2026&utm_content=brand_intro` |

**韩文长文大纲（正文体裁：브랜드 + 제품 개요，非单篇功能教程）**

1. **제목（品牌词尽量靠前，与对外商标一致）**  
   - 例（择一并韩审）：`ThetaWave(쎄타웨이브)는 무엇인가? 대학생용 AI 노트 플랫폼 한눈에`  
   - 或：`thetawave.ai의 ThetaWave — 강의·영상·파일을 복습 자료로 바꾸는 AI 노트`

## 六、可发现性：在 Naver 内怎么「站得住」

（摘要自 [Naver-Blog-发布与编辑指南 四](../../Naver/Naver-Blog-发布与编辑指南.md#四可发现性naver-内--站外搜索实务)；排序公式 **非 Naver 公开保证**。）

- **高优先级**：标题与首段强相关；**足够篇幅** 说清问题；H2/H3、原创图与替代文本；**主类目稳定**、同系列 **内链 2～3 篇**、**稳定发刊节奏**（如周更）。  
- **中优先级**：发后在 Search Advisor 按官方能力做 URL 类反馈；**自然互动**。  
- **与 Google 的边界**：Naver Blog URL 也可能被 Google 收录，但主战场是 **Naver 生态**；别用 GSC 数据替代 Naver 后台（见 [Naver-Blog 四](../../Naver/Naver-Blog.md#四数据与效果衡量)）。

## 十、UTM 示例（与官网互链时）

在定稿前与营销负责人统一 **命名规则**，示例如下（仅作格式参考，以你们 GA4/分析实际为准）：

- `https://thetawave.ai/?utm_source=naver_blog&utm_medium=social&utm_campaign=kr_growth_2026&utm_content=first_post`  
- 或指向具体功能页时把 path 与 `utm_content=lecture_to_notes` 等对齐。

避免同一活动混用多套现短链导致归因混乱。
