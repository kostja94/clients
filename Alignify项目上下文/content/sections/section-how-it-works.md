# 技术概述（How It Works）章节最佳实践

本文档定义技术概述章节的规范，适用于 Tools 页面中说明工具技术原理的章节。

**参考**：[section-consistency](../content-rules/section-consistency.md)、[template-tools](../templates/template-tools.md)、HowItWorks 组件（`src/components/HowItWorks.tsx`）

---

## 〇、字数层级：硬底线 vs 建议（必读）

| 层级 | 适用 | 说明 |
|------|------|------|
| **A 硬底线** | advantages 数量、内链存在性、禁止产品名、禁止 mid-word 截断、绝对字数下限 | 不因「博客化」放宽 |
| **B 强建议（标题）** | H2 标题格式 | 中文 `[类型]如何工作`，英文 `How [Type] Work` |
| **C 软建议（正文字段）** | technologyBase、architectureDifferences、单条 advantage 字数 | **以下为建议区间**，以**说清技术链路、段落自然**为先；勿为贴数字删补句式 |

**一致性重新定义**：跨页优先对齐 **H2 语气、信息顺序**；字段字数允许在建议区间内随主题难度浮动。字段间避免 **约 3 倍以上** 长短悬殊即可，**不**要求逐字段字数相等。

---

## 一、定位与作用

**技术概述**是解释工具技术原理的章节，核心作用是：

- **技术基础（technologyBase）**：介绍技术基础、核心原理，涉及的主要技术与建模方式
- **核心优势（advantages）**：列出 3-5 个主要技术优势
- **架构差异（architectureDifferences）**：说明不同工具类型的技术架构差异

---

## 二、通用规范

### 2.1 使用 HowItWorks 组件

Tools 页面的技术概述章节应使用 `HowItWorks` 组件。

**组件 Props**：
- `id`：章节锚点 ID
- `title`：H2 标题
- `technologyBase`：第一段，技术基础描述
- `advantages`：优势列表，`{ name, description }[]`
- `architectureDifferences`：第三段，技术架构差异
- `locale`：可选，`'zh' | 'en'`

### 2.2 篇幅（A 硬底线 + C 软建议）

| 项目 | 层级 | 中文 | 英文 | 违规后果 |
|------|------|------|------|----------|
| **advantages 数量** | **A** | 3–5 条 | 3–5 条 | 少于 3 或多于 5 为硬违规 |
| **内链** | **A** | ≥ 1 个强相关内链 | ≥ 1 个强相关内链 | 无内链为硬违规 |
| **禁止产品名** | **A** | architectureDifferences 不得出现具体产品名 | 同左 | 硬违规 |
| **EN 截断** | **A** | — | 禁止 mid-word 截断 | 硬违规 |
| **tb 绝对下限** | **A** | ≥ 100 字 | ≥ 50 词 | 防止信息空洞 |
| **arch 绝对下限** | **A** | ≥ 60 字 | ≥ 30 词 | 防止信息空洞 |
| **technologyBase** | C | 约 220–420 字 | 约 140–280 词 | 以说清原理链路为先 |
| **architectureDifferences** | C | 约 120–280 字 | 约 90–200 词 | 以说清架构差异为先 |
| **单条 advantage** | C | 约 35–80 字 | 以可读、可比为准 | 同页各条宜长度相近 |

**统计方法**：去除 HTML 标签后，中文数字数，英文数词数（`len(text.split())`）。

### 2.3 生成时注意事项

- **篇幅**：明显过短（说不清）或单段占满屏时重写；**不**为贴区间硬删技术句
- **英文深度**：与中文**信息深度**相当即可，**不必**字符数机械对齐；不足时意译补充，超标时按句截断
- **英文截断**：按**完整句子**截断，**禁止 mid-word 截断**（如 "pronun"、"generatin"）——此为 A 硬底线
- **深度**：避免为省词删掉必要限定（合规、输入假设、失败模式）
- **发布前检查**：以**可读与无截断词**为准，而非旧版「字符窗口」硬指标

### 2.4 标题格式

- **中文**：`[工具类型]技术如何工作` 或 `[工具类型]是如何工作的`
- **英文**：`How [Topic] Work` 或 `How [Tool Type] Work`
- **语法检查**：❌「如何变声器工作」→ ✅「变声器如何工作」

## 三、内容要求

### 3.1 技术基础（第一段）

- 介绍技术基础、核心原理
- 涉及的主要技术（如 GAN、扩散模型、Transformer 等）
- 与传统方案的对比优势
- **避免重复**：不重复「什么是」中已描述的「多种输入」「完整音乐」「降低门槛」等，聚焦技术实现（如训练数据、建模方式、生成流程）

### 3.2 优势列表（第二段）

- 使用 `<ul>` 列表，每项格式：`<strong>名称</strong>: 描述`
- 3-5 个核心优势
- 避免过于技术化，保持可读性

### 3.3 架构差异（第三段）

- 说明不同工具类型的技术架构差异
- 针对不同用例的优化方向
- **避免与「什么是」重叠**：不重复「完整音乐生成」「多种风格」等功能价值描述，聚焦技术实现差异（如文本编码器、序列生成、多轨道架构等）
- **避免列举具体产品**：架构差异描述工具类型即可，具体产品（如 Suno、Udio）在 BestTools 章节详述

## 四、备注：SEO/Marketing 页面

SEO、Marketing 页面通常**不使用** HowItWorks 组件，而是使用 `Section` 组件编写纯文字技术说明，标题格式如「XXX 如何工作」。

## 六、标题、重复与常见错误

**标题语法**：❌「如何变声器工作」→ ✅「变声器如何工作」；谓语 + 主语 + 疑问词顺序正确。

**章节重复**：若「技术概述」与「XXX 如何工作」内容相同，合并为一个「XXX 如何工作」；避免功能对比表与工具详情、应用场景与使用说明重复。

**常见错误**：标题语法错误、与「技术概述」重复、单段信息过密或整章过短说不清；✅ 使用 HowItWorks 组件，标题格式正确。

**生成时常见错误**：

| 错误 | 说明 | 正确做法 |
|------|------|----------|
| mid-word 截断 | 英文超标时截断到单词中间（如 "pronun"） | 按完整句子截断，保证句子完整 |
| 列举具体产品 | architectureDifferences 中出现 Suno、Udio 等产品名 | 描述工具类型/架构差异，具体产品在 BestTools 中 |
| 与「什么是」重复 | technologyBase 重复「降低门槛」「多种风格」等 | 聚焦技术实现：训练数据、建模方式、生成流程 |
| 英文过度精简 | 为达标删减导致信息缺失 | 意译保持深度，不足时补充、超标时按句截断 |
