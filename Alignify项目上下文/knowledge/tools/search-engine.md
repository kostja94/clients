## 词汇锚点

- **AI search engine（AI 搜索引擎）**：在公开网页（或厂商允许的数据源）上检索后，由 **LLM** 汇总为**自然语言答复**，并常附 **引用链接**；相对传统「十条蓝链」，交互更接近**对话式研究助手**。选型时建议同时看**默认是否展示引用**、**能否一键打开原页**，而非只看摘要文笔。
- **Answer engine / generative search**：强调**直接答案**而非排名列表的营销说法；与 **AI Overviews**、**AI Mode** 等**站内产品名**相邻。不同地区、账户类型下，同名功能**是否可用、默认展开与否**常有差异，不宜用一次演示概括全局。
- **Native AI search**：自产品成立即以「问答 + 检索」为主路径（如常被讨论的 **Perplexity** 类产品形态）；与「传统搜索框 + 后来加一层摘要」的演进叙事不同。前者往往把**订阅与垂类模式**写进主路径，后者更常承接**存量搜索流量与广告位**。
- **Integrated LLM search**：在**大模型对话产品**或**传统搜索引擎**里打开「联网」「Search」开关，由同一账号体系完成检索与生成；**索引与合规边界以各产品披露为准**。同一品牌下，**聊天窗里的联网**与**搜索页里的 AI 条**可能走不同后端与配额。
- **Grounding / citations**：模型输出是否绑定可点击来源；无引用或引用不准时，**幻觉**风险与 **YMYL**（医疗、金融等）场景责任边界更敏感。实务上可区分「有链接但文不对题」与「完全无链」两类质量问题。
- **Deep research / multi-step search**：自动拆解子查询、拉多页再综合；延迟与成本高于单次检索，常与「研究向」套餐绑定。适合**文献综述式**任务，不适合要求**秒回**的轻量查词。

## 浏览器 vs 搜索引擎（易混点）

二者常一起出现（例如「在浏览器地址栏搜索」），但**不是同一层产品**：

| | **浏览器（Browser）** | **搜索引擎（Search engine）** |
|---|------------------------|--------------------------------|
| **解决什么问题** | **渲染与交互**：打开 URL、多标签、扩展、部分场景下 **Agent** 代替点击与填表 | **找信息**：在索引（多为网页）上匹配查询、排序；AI 时代再**生成摘要答案** |
| **典型交付物** | 安装包 / 系统 WebView；**不**自带全网索引 | 查询框或 API；**核心资产**常是**索引 + 排序/摘要模型** |
| **用户心智** | 「我上网的壳子」——同一浏览器可换默认搜索引擎 | 「我问问题的地方」——同一引擎可在不同浏览器里打开 |
| **与 AI 叠合时的判据** | **AI 浏览器**：**AI** 深嵌标签栏、侧边栏、跨页 **Agent**（见 [browser.md](./browser.md)） | **AI 搜索引擎**：首要交互仍是**问句 → 答案/引用**，不必安装独立浏览器 |
| **重叠带** | 浏览器默认搜索框、**Copilot in Edge** 等 = **壳 + 搜索/对话能力** 打包；评测时宜拆成：**壳能力** vs **搜索/模型能力**谁贡献更大 | 纯网页版 AI 搜索**不需要**用户换浏览器 |

一句话：**浏览器是「跑网页与自动化」的客户端；搜索引擎是「从海量网页里找并呈现信息」的服务**。AI 两边都在做，但**选型时先分清你要换的是「上网工具」还是「问答式检索服务」**。

**补充**：企业环境里，**默认搜索引擎策略**（组策略、MDM）会限制「地址栏到底问谁」；这与「是否允许安装某款 AI 浏览器」往往是**两条审批线**，落地时不要混成同一工单。

## 专题对照 / 扩展定义

| 维度 | **偏「独立 AI 搜索」产品** | **偏「大厂搜索里的 AI 模式」** |
|------|---------------------------|--------------------------------|
| **入口** | 独立域名/App、订阅墙与垂类（学术、开发）常见 | 在 **Google**、**Bing** 等内开启 **AI Mode** / **Copilot** 等 |
| **索引与合规** | 各产品自建或与第三方检索 API 组合；引用风格差异大 | 常与现有网页索引、地域政策强绑定；功能分阶段 rollout |
| **争议焦点** | 引用质量、是否「绕过」出版商、订阅性价比 | **零点击**对站长流量影响、品牌词与 **SERP** 形态变化 |

| 维度 | **`search-engine`（终端产品）** | **`web-search-api`（开发者 API）** |
|------|----------------------------------|--------------------------------------|
| **主问题** | 哪个更好用、更准、更敢信？ | 哪条 API 适合 **RAG/Agent**、配额与字段是否够？ |
| **典型用户** | 研究者、营销、普通知识工作者 | 工程师、数据/AI 平台采购 |

**收束**：同一团队内可并存「内容/增长同事看 **search-engine**」「平台/工程同事看 **web-search-api**」——**会议对齐时用一张表分清验收指标**，避免用 API 的 QPS 去评终端产品的「答得好不好」。

## 问题域（为何会出现这类产品）

- **从关键词到意图**：短查询无法覆盖真实任务链，用户想要**多轮澄清**与**一次性读完的摘要**。同一问题在不同轮次会**细化约束**（时间范围、地区、数据来源），对话式界面比反复改关键词更自然。
- **传统 SERP 的信息摩擦**：逐条点开、自行拼接证据慢；**AI 摘要**缩短路径，但引入**来源可信度**新问题。对「扫一眼对比多个观点」与「要一个能交差的结论」两类需求，适合的产品形态也不尽相同。
- **答案引擎与内容生态的结构性张力**：传统搜索通过「展示链接→用户点击→站点获得流量」形成三方回路；AI 搜索在答案内消化信息后，**用户可能不再离开搜索引擎**——这改变了出版商、搜索引擎与用户间的价值分配，也是「零点击加剧」与「内容供给激励下降」讨论的底层逻辑。
- **大模型落地场景**：**联网**减少「训练截止期」导致的事实错误；与 **chat** 产品形态天然契合。落地时仍需区分**可公开检索**与**需登录/内网**的信息边界。
- **商业与生态**：订阅、企业席、API 转售、与浏览器/云账号捆绑；**与出版商、广告商**的利益分配仍在演进。
- **语言与区域**：非英语查询下，**索引覆盖、摘要语言、引用站点偏好**可能显著不同；跨区域团队不宜只以单一语种 demo 定标。

## 能力栈（概念拆分，非厂商功能表）

- **检索 + 生成**：底层可能是传统关键词检索、向量检索、或混合；上层统一为**可读答复**。工程上常分为「先搜后写」与「边搜边写」两类管线，失败时的**回退策略**（仅返回链接、仅摘要、拒答）影响体验。
- **引用与可验证性**：脚注、行内链接、来源卡片；是否支持**逐句对齐**因产品而异。团队规范可规定：**无引用则不得写入对外材料**，以降低甩锅成本。
- **多轮与指代消解**：追问「上面第二条」「对比 A 和 B」依赖对话状态与**会话级上下文**。
- **多模态**：上传图片、图表问答；依赖 **Vision** 与检索链路的耦合方式。
- **垂直模式**：学术、代码、股价、旅行等——**索引或工具插件**（计算器、地图）可能切换。切换模式时若**未明示当前索引范围**，用户容易误判答案完备性。
- **自动化研究**：长耗时、多子查询任务；与轻量「一问一答」常分层计费。
- **导出与协作**：是否支持**剪藏、团队空间、报告导出**（Markdown/PDF）影响研究工作流能否落地，与「模型是否最强」无必然对应。

## 形态谱系（与具体品牌解耦）

- **原生对话式 AI 搜索**：从第一天即围绕「提问—引用答案」设计增长与付费点。
- **传统搜索引擎 + 生成式摘要**：在既有索引上叠加 **AI Overviews**、**AI Mode** 等；**默认是否展开、地域差异**影响体验。
- **聊天产品 + 联网开关**：通用 **LLM** 内嵌「Search / 联网」工具，产品边界介于 **search-engine** 与 **llm**。
- **开发者向 / Pro**：同一品牌下再卖 **API** 或高阶研究——与 [web-search-api.md](./web-search-api.md) 交叉。
- **区域与合规分叉**：同一全球品牌在不同司法辖区的功能列表可能不一致——**以当地产品页为准**。
- **与站内搜索的混淆**：企业 **portal / 文档站** 内检索有时也被口语称为「搜索」，但索引多在**私域**；本页 **search-engine** 语境默认是**公网或可公开访问的网页证据链**，除非文内另作说明。

## 风险 · 合规 · 引用与版权（外部框架可对照，非法律意见）

- **事实性与幻觉**：生成层可能「合理但错误」；高 stakes 场景需**人工核对原文**。
- **来源偏见与 SEO 操纵**：若排序或 snippet 可被商业利益影响，「引用」未必等于「公正」。
- **隐私**：查询是否用于训练、是否长期存档；企业是否提供**零训练**或区域驻留需查条款。
- **出版与版权**：摘要长度、整段改写、付费墙内容是否被间接呈现——各地诉讼与行业协议仍在变化。
- **未成年人与敏感域**：部分品类限制或年龄门，依平台政策更新。
- **品牌与安全**：仿冒站点、钓鱼页也可能被索引进「看似可信」的 snippet；**引用存在 ≠ 引用可信**，仍需域名与证书习惯校验。

## 落地碎片（无先后）

- 先分清：**快问快答** vs **长程研究**；后者看是否支持多步检索、导出与团队共享。
- 需要「可引用」时：优先看**脚注是否链到可核对段落**，而非只看答案流畅度。
- **专业域**（法律、医疗）：把 AI 搜索当**起点**而非终点；对照一手来源与资质要求。
- 与 **浏览器**选型解耦：可先固定一个 AI 搜索引擎，再在任意浏览器打开；除非你需要 **Agent 代操作**再评估 [browser.md](./browser.md)。
- 自建产品：终端体验走 **search-engine** 竞品调研，工程接线走 [web-search-api.md](./web-search-api.md)。
- **日志与审计**：若答案将用于**合规留痕、客服工单、研究结论**，需事先确认**查询与点击日志**保留策略，与「个人随便问问」场景要求不同。

### 行业注记 · 2026 年 AI 搜索格局

- **「零点击」加剧**：Google AI Overviews 在全球 100+ 国家推出后，传统有机链接点击率持续下滑——内容生态与搜索引擎之间的价值分配尚未重建。
- **Perplexity vs Google 的对决**：Perplexity 以独立 AI 搜索 + Instant Buy + Comet 浏览器三线扩展，Google 以 Search + Gemini 一体化防御——2026 年两者都在验证「订阅制 AI 搜索是否可成为独立商业模式」。
- **You.com 从消费级退场**：2025-2026 年从消费级 AI 搜索转型为企业搜索 API 平台（$100M Series C @ $1.5B）——独立 AI 搜索创业公司的 B2B 出口路径成为行业信号。
- **GEO 成为 SEO 必修课**：约 15-25% 搜索流量来自 AI 引擎，结构化数据（Schema/JSON-LD）和实体标识远超传统 blue link 时代的重要性。
- **区域合规分叉**：欧盟 DMA 对默认搜索引擎的约束、中国百度封闭生态、印度/东南亚本地语言需求——AI 搜索的区域化合规成为新维度。

### 对比与测评（第三方；观点非官方）


> **产品动态**：You.com 已于 2025–2026 年从消费级 AI 搜索转向企业搜索 API 平台（$100M Series C @ $1.5B，现为 DuckDuckGo/Windsurf/Databricks 等提供搜索 API），参见 [web-search-api.md](./web-search-api.md) 中的 You.com Search API 条目。本文不再将其列为消费搜索产品。
2025–2026 年英文科技媒体与社区常比较 **Google AI Mode**、**Perplexity**、**ChatGPT 联网**等在**引用透明度、多模态、深度研究耗时**上的差异；共识更多是「**没有单一全能**」，而是按**是否刚需 Google 生态登录**、**是否重视逐条引用**、**是否愿意付订阅**来选。**AI 浏览器**横评则会单独测 **RAM**、**自动化权限**与 **SPA 稳定性**——与纯 **AI 搜索**的「答得准不准」评测维度**不完全重叠**。中文社区亦常讨论**国内可访问性、支付与发票、中文信源覆盖**，与英文评测维度并列时需单独建表。*本小节为网摘综合，非 Alignify 实测。*
