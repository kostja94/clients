## 一、核心论点（如果听众只记住一句话）

> 同时服务 20 家 AI 公司——不是我的极限，是我选择的生活节奏。
> Agent 把我的执行层接了，所以我只用三分之一的时间做客户，
> 剩下三分之二，学习、实验、构建自己的产品。

**演讲的深层信息**：这不是一个"我很拼"的故事。这是一个"我设计了这样一个系统，让赚钱和做产品不互斥"的故事。Agent 不是让我更忙——是让我有时间做自己的事。

### Part 1：我是怎么走到这里的（3-5 min）：三阶段演化

**这部分是新增内容——用个人演化替代抽象的"旧范式 vs 新范式"对比，更真实、更有记忆点。**

**Slide 2: 三阶段演化（时间线）**

| 阶段 | 时间 | 交付能力 | 工作状态 |
|------|------|----------|----------|
| 阶段一 | 创业初期 | 每周每客户 1 小时会议 + 手动编辑文档、方案、表格 | 一个人只能服务 2-3 个客户，大量时间做执行 |
| 阶段二 | 2025 年 6 月起 | 可交付网站（Lovable vibe coding），Oginify 完全 vibe coding 出来的 | 效率跃升——能做完整带后端的产品，SEO 前端界面更不在话下 |
| 阶段三 | 2026 年起 | Agent 生成各类 MD 文档 + 可部署代码仓库 + Skills + Agent 可消费的双轨文档 | 20 家客户稳定运转，同时维护自己的产品和博客 |

**演讲要点：**
- "这不是一蹴而就的。刚开始我每周花在一个客户上的时间是一小时会议，加无数手动编辑的文档、方案、表格。"
- "去年六月是转折点——我接触了 vibe coding。Lovable 让我能交付网站了。Oginify 就是完全 vibe coding 做出来的——连完整的带后端的产品我都能做了，更不用说用于 SEO 的前端界面。"
- "今年开始，我能交付各种形态的文档——包括可部署的代码仓库、Skills、以及各种类型的 Markdown 文件。"
- 强调：Lovable 可视化做得好，上手难度低，相比于 Cursor——这让非技术人员也能看到可点击的网站原型。

**Slide 3: 关键洞察——时间去哪了**

- 一张饼图或对比：
  - 阶段一：80% 执行 / 15% 策略 / 5% 学习
  - 阶段三（现在）：33% 客户交付（策略+审核）/ 33% 自我学习 / 33% 自己的产品
- 底部标注：Agent 把执行层接了，人的判断力用在刀刃上

**演讲要点：**
- "Agent 接的不是我的策略判断——接的是我的重复性执行工作。"
- "我今天学到的，下周就出现在客户的增长方案里。而客户只看到交付质量，不需要知道我用了什么工具。"

### Part 2：一周长什么样（5-8 min）：批处理与 A2A 协作

**Slide 4: 一个画面——批处理**

- 核心画面描述："我同时打开好几个窗口，为不同客户解决同一个问题。"
- 同一类任务（如所有客户的关键词调研、所有客户的竞品分析），在同一个时间段批量完成
- Agent 切换客户时无上下文损耗——不像人类需要"进入状态"
- 效果：别人 1 小时做 1 个客户，我 1 小时做完 20 个客户的同一类任务

**演讲要点：**
- "我不是多线程。我是批处理。"
- "同一类任务、同一天、同一个 Agent 工作流。切换客户只改几个参数，Agent 不累，我不需要'重新进入状态'。"
- "这跟传统顾问完全不同——传统顾问每切换一个客户，需要重新读材料、重新对齐、重新开会。我的 Agent 不需要。"

**Slide 5: A2A 协作模型**

- 不是人对人，是 Agent 对 Agent
- 我的 Agent → 生成双轨文档（人读部分 + Agent 读部分）→ 客户的 Agent 直接消费
- 客户侧：即使只有一个实习生、只要能用 Agent，就能完整跑完整套流程
- 文档本身就是可执行的 Agent 输入——不用再开会翻译

**演讲要点：**
- "我不喜欢 teamwork——以前招过实习生，感觉很难配合。"
- "但我不是一个人在扛。我的协作对象不是人，是 Agent。"
- "我的 Agent 生成文档，客户的 Agent 消费文档。这是 A2A，不是 B2B。"
- "一份 MD 文档里，有人读的部分，也有 Agent 读的部分——结构化数据、检查清单、命令——Agent 可以直接执行，人只需要确认。"

**Slide 6: 四套交付方案（根据客户团队能力）**

| 方案 | 客户条件 | 我的交付 | 客户要做的 |
|------|----------|----------|------------|
| 方案一 | 团队人员充足，有前端 | Lovable 原型 | 客户 1:1 拷贝到自己网站 |
| 方案二 | 有技术但没前端 | Lovable 原型 → Agent 转 Next.js/React 代码仓 | 客户部署到自己服务器 |
| 方案三 | 有运维但没前端 | Next.js 代码仓（我托管）+ Rewrite 代理 | 客户只加一条 rewrite 规则 |
| 方案四 | 一个人都抽不出来 | 我代运营内容更新 | 客户等有人了再接过去 |

**演讲要点：**
- "Lovable 做前端架构 SEO 不友好——所以我不改变内容，只改变前端架构，用 Cursor 或别的 Agent 把项目转成 React + Next.js。"
- "转了以后对方的技术配置一条 rewrite 转发到我的项目——我就完整抽身出去了。"
- "即使对方只有一个人、能用 Agent，这套流程就能跑通。"

### Part 3：工程化底座（8-12 min）：标准化 + 规模化

**Slide 7: 标准化体系——每个客户 6 核心文件**

- 展示 client-template.md 的核心理念
- 每个客户：features / competitors / keywords / site-structure / use-cases / growth-strategy
- 可选扩展：brand-visual、project-tasks、skills-ecosystem、data-attribution、agent-readiness-report
- 509 个 Markdown 文件，8.5MB，全部 Agent 辅助生成 + 人工审核
- 三种维护模式：冷启动 A / 存量整理 B / 增量精炼 C

**演讲要点：**
- "工厂流水线——每个客户进来，六份核心文件先铺上。Agent 按模板生成，我审核后交付。"
- "这不是创意工作，这是工业化生产。但工业化不代表质量低——因为我的时间从执行转到了审核和策略。"
- "模板本身也在迭代。服务一个客户的洞察，会沉淀到模板里，下一个客户自动受益。"

**Slide 8: 交付物多样性（远超基础六件套）**

- 展示不同类型的交付物（只列类型，不提客户名）：
  - 技术诊断报告：GSC 数据驱动 + curl 验证命令（如"某 SPA 站 8,857 页未索引，只有 2 页索引"）

  - Skills 生态策略：五阶段路线图 + 关键词策略
  - Product Hunt 发布全案：发布策略、落地页、社媒矩阵
  - 品牌视觉规范 + 风格审计
  - 多语种本地化方案（如韩语考试市场竞品分析）

**演讲要点：**
- "同一个 Agent 工作流，不同客户不同输出。"
- "有客户之前在 Google 上几乎不可见——诊断后发现 SPA 空壳、重复标题、缺 canonical。解决方案写成 MD，附带 curl 验证命令——国内前端开发不用读 Google 文档就能直接改。"

**Slide 9: Demo 漏斗——32 个潜在客户的起点**

- 每个潜在客户都给 demo（展示 demo 文件夹 32 个项目）
- Demo 内容：competitors / keywords / features / use-cases / site-structure 等
- 部分 demo 包含 Lovable 原型 HTML 落地页

**演讲要点：**
- "我不做 outreach——所有客户都是朋友推朋友，客户推客户。"
- "但每个潜在客户我都会给 demo。不是 PPT 演示——是真的分析文档。"
- "Demo 就是交付样本。客户在签合同之前，已经知道我的工作质量了。"

### Part 4：更大图景（12-15 min）：1/3 时间去哪了

**Slide 11: 时间分配——这是一个设计，不是一个事故**

- 1/3：客户交付（20 家公司）——策略 + 审核
- 1/3：自我学习——新工具、新模型、新增长打法
- 1/3：构建自己的产品——Oginify + Alignify

**演讲要点：**
- 这一段是整个演讲的情感高点
- "很多人问我：服务 20 个客户不会 burnout 吗？不会。因为 Agent 帮我做了执行层的事情，我反而有更多时间去学习、去 build、去思考。"
- "20 不是我的极限。是我想控制自己的频率——因为我还需要自己做产品。"

**Slide 12: Oginify —— Dogfooding 的产物**

- Oginify：AI OG Image Generator
- 来源：客户需要 pSEO + 大量页面 + 社媒分发 → 做了这个工具
- 完全 vibe coding 构建
- 这是"狗食狗用"——客户的需求变成了自己的产品，自己的产品又反哺客户

**演讲要点：**
- "Oginify 就是在这种节奏下做出来的。不是为了赚钱——是因为客户有需求，我自己也需要，顺便做成了产品。"
- "这就是 Agent 赋能的真正含义：不是让你做更多客户项目，而是让你有时间做你自己的事。"

**Slide 13: 自我学习 → 反哺客户**

- 每天试用新 AI 工具、读论文、跑实验
- 学习成果直接转化为客户项目的策略输入
- "我今天学到的，下周就出现在客户的增长方案里"
- 这就是为什么不需要 outreach——别人主动来找你，因为他们知道你在前沿

### Part 5：诚实面对（15-17 min）：边界与教训

**Slide 14: 边界与风险管理**

- Agent 不会出错——因为所有输出都经过人工审核（"我比 Agent 更慢、更仔细"）
- 客户流失与质量无关——是配合上的问题、合作阶段不对、或 founder 没有合理定位
- 不是所有客户都适合这个模式：
  - 需要大量同步会议的团队不适合
  - 不理解"异步优先"的团队不适合
  - 把顾问当执行人力的团队不适合
- Solopreneur 的代价：找不到合适的帮手——实习生配合不了，不是他们的问题，是这个模式天然排斥多人协作

**演讲要点：**
- 不回避问题，诚实但不自辩
- "Agent 没出过错——不是 Agent 完美，是我审核得好。Agent 比人靠谱多了，因为它不会累、不会忘、不会情绪化。出问题都是我没审到。"
- "客户流失不是因为我的交付不行——是配合。有些 founder 觉得找一个外部顾问就应该'搞定一切'，不配合不投入。这种客户就是阶段不对。"

### Part 6：你可以带走什么（17-19 min）：行动框架

**Slide 15: 给 AI 产品团队的行动框架**

1. 接受异步优先——减少同步会议，拥抱结构化文档
2. 提供上下文而非指令——给顾问目标、约束和背景
3. 建立共享知识库——品牌指南、产品文档 Agent 可直接读取
4. 用结果衡量，不用工时衡量——Agent 赋能的效率提升不应被"小时费率"思维限制
5. 即使只有一个人 + Agent，也能跑通整条增长流水线

**Slide 16: 三点总结**

1. Agent 不是让我更忙——是让我有时间做自己的事
2. A2A 不是未来的概念——是我现在的日常。Agent 写给人读和 Agent 读的双轨文档，客户的 Agent 直接消费
3. 飞轮越转越快——每服务一个新客户，模板、Skills、方法论都沉淀一层，下一个客户零冷启动

## 四、核心叙事线索（贯穿全演讲的暗线）

四条暗线，不一定会明说，但每张 slide 都服务于至少一条：

1. **从挣扎到设计**：不是一开始就这么高效——三阶段演化本身就是故事

4. **A2A 是新的协作范式**：人对人的沟通成本高，Agent 对 Agent 是异步、可复用、无摩擦的
