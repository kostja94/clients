## 〇、两条主轴：原生电商构建器 vs Vibe Coding 建站

采购心智上，Runner AI 常被放在两类产品的交叉区间之外或之间：**一类是「店铺操作系统」型原生电商**（以 Shopify 为代表），**一类是「对话生成前端 / 全站代码」型 vibe coding 工具**（以 Lovable 为代表）。内容策略上宜**分轴写清**：前者比「交易与生态」，后者比「电商域模型与增长栈」。

### 方向 A：原生电商构建器（Shopify 类）

**典型特征**：以 **在线交易**为第一性原理；**结账、库存、税务、履约、渠道、App 生态、B2B/线下 POS** 等能力纵深大；商家心智是「我在经营一家店」，而不是「我生成了一个站点」。

| 子类 | 举例（不完全） | 强项 | 与 Runner 比较时的诚实框架 |
|------|----------------|------|---------------------------|
| **店铺 OS** | Shopify、BigCommerce、WooCommerce（WordPress） | 生态、扩展性、市场信任、合作伙伴网络 | 比「谁能更快搭壳」不如比 **一体化商业工具 + 自动增长实验**是否覆盖目标商户阶段；大企业/complex B2B 仍以 OS 类为主干为常态 |
| **平台内 AI** | Shopify Magic、Sidekick 等 | 在**既有店铺工作流**内嵌文案、运营辅助 | Runner 可强调 **从零生成店铺域模型 + 内置营销/实验栈** 的打包路径；避免断言「替代 Shopify 全栈」除非产品边界已公开确认 |
| **主题/建站层** | OS2.0、第三方主题、Remix | 品牌化与前台自由度 | 官网已有 **Remix Shopify Theme** 等叙事时，适合放在本轴下讲 **协同/增强** 而非简单替代 |

**Runner 可用叙事角度（示例）**

- **切入点不同**：Shopify 是「选平台 → 装栈 → 增长」；Runner 侧重点是 **Prompt 生成可卖货的店 + 原生运营工具 + 自动 CRO**，适合要从 0 收敛工具账单与实验摩擦的团队。  
- **插件经济学**：Shopify 常伴 **多 App 订阅**；Runner 若以「少插件的一体化」为卖点，需用**可核对**的功能列表与 TCO 假设，避免笼统「更便宜」。  
- **增长层**：若 Runner 的 A/B、多变量与行为优化为「出厂标配」，可与「需另购 Optimizely 类 / 多个分析+实验工具」的栈对比——以**商户规模与合规**为限定语。

### 方向 B：Vibe Coding / AI 网站生成器（Lovable 类）

**典型特征**：以 **自然语言迭代** 生成界面与逻辑，强调「与 AI 一起改代码/改产品」的 **vibe** 体验；产出常常是 **通用网站、SaaS landing、工具站**，默认 **商品目录、购物车规则、支付、履约、多市场税务** 等**电商域**能力未必是第一公民。

| 子类 | 举例（不完全） | 强项 | 与 Runner 比较时的诚实框架 |
|------|----------------|------|---------------------------|
| **Vibe coding / AI app builder** | [Lovable](https://lovable.dev/) 等 | 通用产品迭代速度、工程友好、可视化+对话改 UI | 适合讲「**要卖货 + 要少拼接**」选 Runner；「要任意 Web 应用/强定制代码路径」可能仍偏 vibe 工具 |
| **AI 前端 / 设计到代码** | v0、Bolt、Framer+AI 等 | 组件级 UI、品牌站 | 与 Runner 比：**电商交易深度、Listing、促销与结账、内置 CRO** 是否为默认能力 |
| **代码托管与部署** | GitHub、Vercel 等链路上的产品 | 开发者工作流 | Runner 若面向 **商户/运营**而非**工程团队**，宜强调 **无需维护代码仓库** 的门槛优势（若属实） |

**Runner 可用叙事角度（示例）**

- **域专注**：Runner 主打 **e-commerce domain**（店铺、商品、转化工具），vibe coding 主打 **通用 software/website generation**；对比页可用「**commerce primitives** 是否开箱」做 checklist（购物车、结账、税务/政策占位、库存叙事等——以产品实际为准）。  
- **增长闭环**：vibe 工具很少默认打包 **持续 A/B 与多变量 + 行为驱动** 的商家增长叙事；这是 Runner 与「纯生成」分野的重点。  
- **用户画像**：Lovable 系更偏 **builder/creator/小团队** 工程心智；Runner 更偏 **店主/运营/增长**——内容投放与素材也应分流。

### 两轴交叉时的「选购问题」（可做成博客/对比页骨架）

1. **你是不是以销售商品与复购为核心？** 是 → 先对齐 **原生电商或电商原生 AI**（含 Runner）；否 → vibe/泛建站更轻快。  
2. **你能不能长期养插件栈与集成？** 不能/不想 → 看一体化与「实验+运营内置」；能 → Shopify + 自选 App 仍是强路径。  
3. **你要的是可部署代码仓库，还是可经营店铺？** 前者偏 Lovable/工程链；后者偏 Runner/Shopify 类。

## 一、竞品分组（采购心智）

| 类型 | 代表方向 | 客户为何比较 Runner AI |
|------|-----------|-------------------------|
| **原生电商 / 店铺 OS** | Shopify、BigCommerce、WooCommerce 等 | **交易、规模、生态、合规**；Runner 是否在特定阶段「更少拼接 / 更快实验」 |
| **Vibe coding / AI 全站生成** | Lovable、Bolt、v0 等 | **对话迭代与生成速度**；是否仍需自补电商栈 |
| **泛 AI 建站** | Wix ADI、Durable、10Web、Framer | 是否专注 **交易闭环**，还是偏展示站 |
| **Shopify 生态内 AI 与主题** | Shopify Magic、主题、Remix、page builder | 与现有店共生还是迁移 |
| **区域/跨境建站** | Shoplazza 等 | 支付、物流、本地化 |
| **新兴 AI 电商栈** | Atlas、Genstore、Kortex 等 | 全栈一体化 vs 单点工具 |
| **纯 CRO/实验 SaaS** | 各类 A/B 工具 | Runner 将 **建站 + 实验** 打包时的边界 |

## 二、简要对照维度（Runner AI 可主打的理性论据）

| 维度 | Runner AI 叙事方向 | Shopify 类常见叙事 | Vibe coding 类常见叙事 |
|------|-------------------|---------------------|-------------------------|
| **起点** | Prompt/聊天生成 **可卖货**的店 + 商品与视觉 | 选主题与栈、装 App、配支付物流 | Prompt 迭代站点/应用，偏通用 |
| **工具栈** | 内置多项 **电商+运营** 能力，减少插件依赖 | **App Store** 深度扩展，按需拼装 | 常需 **自行集成** 支付、商品、第三方 API |
| **增长** | **自动 A/B、多变量** 与持续优化为产品故事中心 | 依赖 App、第三方分析/实验与站内工具 | 通常不默认含 **电商 CRO** 全栈 |
| **买家** | 店主、运营、增长 | 从个体到大企，伙伴生态成熟 | 工程师、独立开发者、轻量团队 |

*具体功能对比必须以**可验证**的产品截图、公开文档或实测为准。*

## 三、关键词层面的竞品词用途

| 竞品词示例 | 内容建议 |
|------------|----------|
| *10Web alternative* | AI 主机+建站 vs **电商原生栈** |
| *Shopify Magic alternative* | 「全店生成+自动增长」vs「店铺内 AI 辅助功能」 |
| *Shoplazza ai* | 区域市场、跨境链路、定价透明 |
| *Atlas / Genstore / Kortex* | 查证各品牌**正式英文名与 Slogan**，避免误写 |
| *Lovable alternative*（电商语境） | 强调 **commerce-first**、结账与增长栈，避免贬损通用生成能力 |
| *AI website builder vs Shopify* | 平衡写「生态/规模」vs「生成与一体化」适用阶段 |
| *vibe coding ecommerce* / *ai build store with chat* | 与 Lovable 轴关键字自然共存，需定义 **电商域**差异 |

## 四、风险与合规

- **商标**：竞品名在广告与标题中的使用需符合各平台商标政策。  
- **虚假对比**：禁编造对方功能缺失；宜用「我们侧重…」而非「对方不能…」。  
- **YMYL**：涉及收入承诺、费率、合规（支付、数据）时需谨慎表述。
