## 一、赛道坐标

| 类型 | 代表产品 | 与 Infron 的重叠 |
|------|-----------|------------------|
| **LLM 聚合 / 路由** | [OpenRouter](https://openrouter.ai/) | 强：多模型单 Key、开发者心智；需对比 Infron 的 **企业 SLA / 支持 / Search·Media 并列** |
| **媒体生成 API** | [fal](https://fal.ai/) | 强：图像/视频等模型 API；Infron 站面 **Media** 产品线需用文档细化差异 |
| **推理云 / 自建集群** | Together、Fireworks、Baseten、超融合云厂商 | 重叠：低价推理；Infron 更像 **跨供应商编排层** 而非单一算力卖家 |
| **云厂商 Bedrock / Vertex** | AWS、GCP | 重叠：企业采购路径；Infron 卖点在 **中立聚合 + 快速换模型** |
| **官方 API** | OpenAI、Anthropic、Google… | 关系：多为底层供应商；Infron 提供聚合与 failover，非替代官方 ToS |

## 二、差异化叙事（站面可引用方向）

| 维度 | Infron 站面主张 | 撰写时注意 |
|------|-----------------|------------|
| 广度 | **400+** 模型、**100+** 供应商 | 数字与竞争对手「模型数」对比易过时 — 标注更新日期 |
| 可靠性 | **99.99%** SLA、自动故障转移 | 需链接 SLA 正文或合同条款 |
| 成本 | pass-through + 缓存 + 最高约 **35%** 优化叙事 | 与用户实际工作负载强相关，避免绝对化 |
| 合规 | ZDR 可用、SOC2 进行中 | 进行中 vs 已认证需措辞严谨 |
| 服务 | 专属频道、**15 分钟内**响应（站面表述）、创始人直达、7×24 | 需与真实服务等级一致，避免广告违法绝对化 |
| 多产品线 | **LLM + Search + Media** | 与「纯 LLM 聚合」形成差异化定位 |

## 三、可能的内容角度（SEO / PLG）

- **迁移指南**：从 OpenRouter / 单一云迁移到 Infron 的 endpoint 与环境变量对照（技术文）。  
- **场景化选型**：「只要 LLM」vs「LLM + 媒体同一账单」决策树。  
- **企业检查清单**：SLA、ZDR、日志保留期、子处理器列表 — 对标采购问卷。

## 四、监视列表（情报）

- OpenRouter、fal、Together 的模型上架速度与定价公关节奏。  
- 云厂商「统一网关」产品是否侵蚀中立聚合层故事。  
- 区域合规（欧盟 AI Act、数据本地化）对 ZDR /  region 路由 的影响。
