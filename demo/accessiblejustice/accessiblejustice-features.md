## 1. 三大核心服务

### 1.1 AI 催款函制备（AI-Generated Demand Letters）

| 维度 | 描述 |
|------|------|
| 输入 | 用户描述纠纷（搬出日期、押金金额、扣款理由）+ 上传证据（租约、照片、房东明细） |
| AI 处理 | 识别索赔点、匹配 California Civil Code §1950.5 相关条款、计算索赔金额（含 2 倍 bad-faith 惩罚） |
| 输出 | 专业催款函——包含日期/地址/事由/法律依据引用/索赔金额明细/回复期限 |
| 律师审核 | 持证加州律师审核案情、证据和文书后方可发出 |
| 格式 | 正式律师函格式，引用具体法条 |

**差异化**：非通用模板——每封催款函根据具体案情定制，引用 §1950.5(g) (21 天期限) 或 §1950.5(l) (恶意扣留 2 倍赔偿) 等不同条款。

### 1.2 小额法庭文书制备（Small Claims Paperwork）

| 维度 | 描述 |
|------|------|
| 核心表格 | SC-100（原告起诉状）及配套文件 |
| AI 制备 | AI 根据案情自动填写诉讼原因、索赔金额、事实陈述 |
| 律师审核 | 律师审核表格内容的准确性和法律充分性 |
| 出庭指引 | 指导用户如何提交法院、送达被告、准备开庭 |
| 开庭限制 | 加州小额法庭不允许律师出庭——用户需自行出庭，但 Accessible Justice 负责庭前准备 |

**关键价值**：小额法庭的程序性门槛（表格填写、送达规则、证据组织）是大多数租客的最大障碍——AI 制备 + 律师审核消除了这一障碍。

### 1.3 全程引导服务（File & Collect Guidance）

| 阶段 | 服务内容 |
|------|---------|
| 催款阶段 | 律师审核后的催款函发出 → 等待房东回应（很多案件在此和解） |
| 诉讼准备 | 若房东不回应 → 制备全套法庭文件 → 律师审核 |
| 法院提交 | 指导用户向对应的加州小额法庭提交文件并缴纳申请费 |
| 送达被告 | 指导用户如何合法有效地向房东送达法律文书 |
| 开庭准备 | 证据组织建议、法庭陈述要点、提问预期 |
| 判决后 | 如胜诉，指导如何执行判决、收取赔偿 |

## 2. 法律覆盖框架

### 2.1 加州法律知识库

Accessible Justice 的 AI 引擎深度覆盖 California Civil Code 第 1950.5 条的全部分款：

| 条款 | 内容 | AI 应用 |
|------|------|---------|
| §1950.5(a)-(e) | 押金定义、金额上限、用途 | 判断押金是否合法 |
| §1950.5(g) | 21 天返还/明细期限 | 自动检测是否超期——最常用的索赔依据 |
| §1950.5(h)-(j) | 可扣款项目及举证要求 | AI 分析每一项扣款的合理性和收据完整性 |
| §1950.5(l) | 恶意扣留——2 倍惩罚性赔偿 | AI 识别 bad faith 模式——如无明细、虚构损坏、超额索赔 |

### 2.2 AI 可识别的违规模式

| 违规类型 | AI 检测方法 |
|---------|------------|
| 超期未返还 | 计算搬出日期 vs 当前日期 → >21 天 = 违规 |
| 未提供逐项明细 | 检测房东是否提供了 itemized statement |
| 明细未附收据 | 检测扣款金额是否有对应收据支撑 |
| 正常损耗被索赔 | 交叉比对 HUD/IRS 折旧表——如 5 年地毯收全价更换费 = 不当扣款 |
| 清洁费过度 | 对比押金金额 vs 清洁费金额 + 是否有照片/收据 |
| Bad faith 模式 | 多因子判断：超期 + 无明细 + 无理扣款 = bad faith → 2 倍赔偿 |

## 3. 律师审核流程

### 3.1 审核层级

```
AI 制备初稿
    ↓
持证加州律师审核
    ├── 案情核实：用户描述是否完整、逻辑是否自洽
    ├── 法律引用：法条引用是否正确、处罚计算是否准确
    └── 文书质量：格式是否符合法院要求、事实陈述是否清晰
    ↓
律师确认/修改后定稿
    ↓
发送给用户
```

### 3.2 律师审核 vs 纯 AI 的价值

| 维度 | 纯 AI 生成 | AI + 律师审核 |
|------|-----------|--------------|
| 法律准确性 | AI 可能生成不存在的法条引用（幻觉） | 律师逐条核实引用 |
| 案情适配 | AI 可能遗漏或曲解案件细节 | 律师理解案情上下文 |
| 法院接受度 | 法官可能不信任纯 AI 文件 | 经律师审核的文件专业可信 |
| FTC 合规 | 纯 AI 宣称可替代律师会面临 FTC 执法（参见 DoNotPay 案例） | 明确技术公司 + 律师服务分离 |

> **DoNotPay 前车之鉴**（2024-2025）：FTC 对 DoNotPay 发起执法行动，指控其虚假宣称 AI 可替代持证律师，且其 AI 输出在法律上不可靠。Accessible Justice 的"AI + 律师"模式直接规避了这一风险。

## 4. 用户流程深度拆解

### 4.1 完整用户旅程

```
用户访问网站
    │
    ├─→ 辨识阶段（是否有合法索赔？）
    │     - 搬出多久了？（>21 天？）
    │     - 收到明细了吗？（有收据吗？）
    │     - 扣款合理吗？（正常损耗被扣了？）
    │     ↓
    │
    ├─→ 录入阶段（Tell us what happened）
    │     在线表单：搬出日期、押金金额、扣款情况、证据上传
    │     ↓ 耗时：几分钟
    │
    ├─→ AI 分析阶段（后台）
    │     AI 识别违规模式、计算索赔金额、草拟文件
    │     ↓
    │
    ├─→ 律师审核阶段（后台）
    │     持证律师逐案审核
    │     ↓
    │
    ├─→ 文件交付阶段
    │     用户收到经律师审核的催款函/法庭文件
    │     ↓
    │
    ├─→ 执行阶段
    │     催款函发出 → 和解（多数案例）→ 成功
    │     或 → 诉讼 → 开庭 → 判决 → 成功
    │     ↓
    │
    └─→ 收费阶段
          成功追回后按约定比例/结构收费（无前期费用）
```

## 6. 定价与商业模式

### 6.1 当前模式

- **无前期费用**（No upfront cost）
- **成功后收费**（Success-based fee）
- 合格案件才接（qualifying cases）——暗示有案件筛选机制

### 6.2 与竞品定价对比

| 产品 | 定价模式 | 覆盖范围 | 价格 |
|------|---------|---------|------|
| **Accessible Justice** | 成功后收费 | 仅加州 | 无前期费用，成功按比例 |
| Rentrieve | 一口价 | 全美 50 州 | $29 |
| DepositHawk | 分层定价 | 全美 50 州 | 待确认 |
| DoNotPay | 订阅制 | 通用法律 | $36/3 个月 |
| 传统律师 | 小时收费 | — | $300-500/小时 |

成功后收费 vs 一口价的关键差异：
- Accessible Justice：零风险给用户，但单案收入更高（成功则收一定比例）/ 适合押金金额较大的案件
- Rentrieve：$29 低门槛吸引大量用户 / 但不管追回多少、难案简单案同价

## 7. 技术基础设施

| 组件 | 描述 |
|------|------|
| 平台形态 | Web 应用（无 App 形态披露） |
| AI 模型 | 基于 LLM 的法律文件生成引擎（疑似 RAG + 法律知识库） |
| 法律知识库 | California Civil Code §1950.5 全条款 + 相关判例 + HUD/IRS 折旧表 |
| 律师网络 | 与持证加州律师的合作/雇佣关系（审核服务由律师提供） |
| 合规标记 | "Technology company — not a law firm. Legal services provided by independent licensed attorneys." |
| 数据安全 | 涉及个人身份信息和法律案件信息——需关注数据隐私合规 |
