## 一、场景概览

| 场景类型 | 核心诉求 | 典型用户 | AgentBoard 价值 |
|----------|----------|----------|-----------------|
| **个人证明** | 量化 AI 编码贡献、晒成果 | 独立开发者、远程工作者 | 分享卡片、多种风格、数据可视化 |
| **社交竞争** | 与全球开发者比拼、爬榜 | 重度 AI 用户、极客 | 排行榜、Today/Week/All Time、打卡式 |
| **DevRel / 个人品牌** | 展示工具使用、建立影响力 | 技术博主、开源贡献者 | Code Wrapped、个人主页、社交分享 |
| **团队/社区** | 谁最会用 AI？量化比较 | 小团队、开源社区 | 公开排行榜、签到文化、量化标准 |
| **工具评测** | 对比 **Claude Code vs Codex** 等实际用量 | 评测者、早期采用者 | 双引擎分区统计、指标透明 |

**类比**：多邻国打卡、扇贝打卡——每日数据、分享、排行榜。

### 同受众生态（非竞品）

与 **Year in Code / 2025 Wrapped** 类产品受众重叠（用量可视化 + 愿意分享）；AgentBoard 为 **持续追踪、日/周/总榜、stats cards**，与 **一次性年度叙事** 不同构，**非替代关系**。产品列表、链接与并列话术 → **[agentboard-competitors.md §七](./agentboard-competitors.md)**；检索词与 SEO 策略 → **[agentboard-keywords.md §7–8](./agentboard-keywords.md)**。

## 二、核心使用场景

### 2.1 个人证明（Social Proof）

**场景**：开发者希望向他人证明自己在用 AI 编码，并展示具体产出。解决「想晒成果？没有好看的方式」的问题。

| 要素 | 说明 |
|------|------|
| **触发** | 面试、简历、个人主页、社交媒体、绩效汇报 |
| **行为** | 安装 AgentBoard → 每日/每周分享 Code Wrapped 卡片（多种风格可选） |
| **产出** | 可分享的统计卡片（My Time、AI Time、Tokens、Code、Commits 等） |
| **类比** | 微信运动步数截图、多邻国打卡、扇贝打卡、GitHub 贡献图 |

**参考**：Apollo.io 对 250+ 工程师的测量显示，AI 工具在测试生成等离散任务上约 6x 提速；AgentBoard 提供可量化的「证明」而非主观描述。

---

### 2.2 社交竞争（Leaderboard）

**场景**：开发者想和全球同行比一比谁「ship 得最多」。

| 要素 | 说明 |
|------|------|
| **触发** | 好奇心、好胜心、社区归属感 |
| **行为** | 每日签到、持续编码、关注排名变化 |
| **产出** | Today / This Week / All Time 排名；Human 时长、AI 时长、Boost、Tokens |
| **类比** | 微信运动排行榜、Strava 骑行榜 |

**参考**：Spotify Wrapped、GitHub Wrapped 等「年度回顾」工具证明，可分享的统计能驱动传播；AgentBoard 做的是「每日/持续」版本。

---

### 2.3 DevRel / 个人品牌（Developer Relations）

**场景**：技术博主、开源贡献者、AI 工具布道师希望展示自己对 Claude Code / Cursor 的使用。

| 要素 | 说明 |
|------|------|
| **触发** | 写教程、做分享、建立「AI 编码」人设 |
| **行为** | 定期分享 Code Wrapped；在推文、博客、视频中引用排行榜；使用个人主页 agentboard.cc/@用户名 |
| **产出** | 内容素材；可信度；工具采用证明；**个人主页**（类似 AI 圈子的 Linktree） |
| **类比** | 「我用 Cursor 写了 X 行代码」→ 有图有数据 |

**参考**：CC Wrapped 创作者指出「every share drives awareness」；AgentBoard 的分享卡片天然适合 DevRel 内容。

---

### 2.4 团队/社区氛围（Team & Community）

**场景**：小团队或开源社区希望营造「一起用 AI 编码」的氛围。解决「团队里谁最会用 AI？没有量化标准」的问题。

| 要素 | 说明 |
|------|------|
| **触发** | 内部 PK、周会展示、新人 onboarding |
| **行为** | 多人安装；关注团队在排行榜的位置 |
| **产出** | 签到文化；轻量竞争；工具采用可见性；**量化谁最会用 AI** |
| **类比** | 公司内部 Strava 俱乐部、微信运动好友榜 |

**参考**：LinearB、DX、Harness 等企业级工具关注组织级 ROI；AgentBoard 更轻量，适合小团队自发使用。

---

### 2.5 工具评测与对比（Tool Evaluation）

**场景**：评测者、早期采用者想对比 **Claude Code、Codex** 等工具的实际使用情况（官网主推广双引擎）。

| 要素 | 说明 |
|------|------|
| **触发** | 写评测文章、选型决策、成本/效率对比 |
| **行为** | 多工具并行使用；用 AgentBoard 统一追踪 |
| **产出** | 跨工具指标；Tokens、时长、Boost 等可对比数据 |
| **类比** | 多设备健康数据汇总 |

**参考**：现网已展示 **Claude Code + Codex**；其它工具以「and more」与产品路线图为准。

## 三、按用户角色划分

| 角色 | 主要场景 | 次要场景 |
|------|----------|----------|
| **独立开发者** | 个人证明、社交竞争 | 工具评测 |
| **产品经理 / 设计师 / 创业者** | 个人证明、Vibe Coding 打卡 | 晒成果、社交竞争 |
| **远程/自由职业者** | 个人证明、客户展示 | DevRel |
| **技术博主 / DevRel** | DevRel、个人品牌、个人主页 | 社交竞争 |
| **开源贡献者** | 个人证明、社区氛围 | DevRel |
| **小团队 Lead** | 团队氛围、谁最会用 AI | 个人证明 |
| **AI 工具评测者** | 工具评测 | 个人证明、DevRel |

## 四、按触发时机划分

| 时机 | 场景 | 行为 |
|------|------|------|
| **每日** | 社交竞争、签到 | 查看今日排名；分享当日卡片 |
| **每周** | 周回顾、团队展示 | 分享 This Week 数据 |
| **求职/汇报** | 个人证明 | 整理历史卡片；展示 AI 编码产出 |
| **内容创作** | DevRel | 将卡片嵌入推文、博客、视频 |
| **工具选型** | 工具评测 | 对比多工具数据 |

## 五、与竞品的场景差异

| 场景 | AgentBoard | Code Insights | WakaTime | VibeLog |

| **成本追踪** | 部分 | ✅ | ❌ | ✅ |
