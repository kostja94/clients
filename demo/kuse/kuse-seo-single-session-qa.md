## 1. 先优化已有页面，还是先继续扩张？

**结论（默认）**：**双线并行，但以「高意图、已有机流量或已收录」的页面为优化优先**，扩张只保留在「明确缺口 / 明确关键词机会」上，避免无限铺新 URL。

| 策略 | 说明 |
|------|------|
| **优先优化** | 已有排名（哪怕 11–30 位）、已有展示/点击、或已进索引的页面；改动 ROI 可衡量。 |
| **控制扩张** | 新页只上「与 ICP、转化路径、或关键词地图一致」的页面；否则容易稀释抓取与内链资源。 |
| **例外** | 若当前站点整体索引质量差、大量页面未收录，应先 **技术/索引/内链骨架** 再谈大规模上新。 |

**可操作规则**：每周固定容量——例如 **70% 时间改旧页 / 补内链 / 补意图**，**30% 上新**；数字可按团队规模调整，原则是 **别让「只铺新不养旧」成为默认状态**。

**与站点路线图对齐**：扩张节奏建议与 [kuse.md](./kuse.md)「内容与页面路线图」中的 Phase（use-cases、垂直能力页、features 等）一致；优先保证 **枢纽页与内链骨架** 清晰，再堆同结构 URL。

**会议补充**：上新不只是为 SEO；**页面要写清 scope**，让用户理解 **功能**；关键词与 SEO 友好应和 **功能描述** 一致。在排除多语言重复前提下，Kuse 侧 unique 页面曾讨论从约 **100+** 中长期扩至约 **500** 量级——**以资源与关键词地图为准**，非硬性指标。

## 2. 已有页面的优化方向

### 2.1 排名尚可（约 7–9 位）但 CTR 低

**是否只用 CTR 观测有失偏颇？**  
有可能。**传统 SERP 的 CTR 与「AI 摘要 / GEO（生成式引擎）里的可见性与引用」不是同一套指标**。若部分流量或品牌曝光来自 ChatGPT、Perplexity、Google AI Overviews 等，**站内 CTR 或 GSC 的 CTR  alone 都不足以描述「是否被 AI 答案引用」**。此外，**同一位置上**若 SERP 出现视频、PAA、多段摘要等，**自然结果的点击会被稀释**，CTR 低不一定等于标题失败。

**会议补充**：会上曾以 **CTR 是否高于约 1%** 作粗筛（需结合排名位置与 SERP 是否含 AI Overview 等）；**AI Overview** 可能使靠后结果的点击 **分布更平均**，不宜单看 CTR 断言成败。

**建议**：

- **仍要优化 Title / Meta description**（以及必要时 **H1 与首段**）：7–9 位时，**snippet 竞争力**常是拉升点击的第一步；对 GEO 也有帮助（清晰实体名、问题式标题、可引用的一句话定义）。
- **并行看**：GSC 的展示/点击/排名 + **品牌词与核心词在 AI 侧的抽样检索**（人工或工具），不要单盯 CTR。
- **避免**：为点击率写「标题党」导致跳出高、或与落地页首屏不一致（会伤长期）。

### 2.2 排名低、未进第一页

**不知道怎优化时，按顺序排查**：

| 顺序 | 检查项 | 典型动作 |
|------|--------|----------|
| 1 | **意图是否匹配** | 搜该词，看前 10 是工具页、文章、视频还是首页；对齐类型与深度。 |
| 2 | **覆盖与差异化** | 是否回答了 PAA/长尾子问题；是否有可引用的定义、步骤、对比表。 |
| 3 | **E-E-A-T 与可信度** | 作者/更新日期、案例、来源链接（尤其 YMYL 或 B2B 决策类）。 |
| 4 | **技术可抓取** | 索引、canonical、重复内容、核心内容是否在首屏或首屏附近。 |
| 5 | **内链与外链** | 是否孤立页；是否有相关权威页指向该 URL。 |

**内容怎么改**：先 **对齐排名前 3 的共性**（格式、长度区间、子话题），再 **做一块对手没写清的「信息增益」**（数据、流程、模板、可下载结构），比盲目加长更有效。

**会议补充**：若长期 **约 20 名开外**，需看 **关键词竞争度与前排站点类型**；极难进前十时，可 **先做长尾 + 内链**，把权重导向核心页，或 **整站聚焦** 少数核心词。

## 3. 英文页与小语种页：是否要人工翻译？

**结论**：**分场景，不必全站一刀切。**

| 场景 | 建议 |
|------|------|
| **高价值市场**（有付费/演示转化、有明确关键词计划） | **人工翻译 + 本地化审校**（至少关键页：首页、定价、核心产品/用例）。机器翻译仅作初稿。 |
| **占位或长尾覆盖** | 可用 **机器翻译 + 人工抽检**；但必须统一术语表（品牌名、功能名），并避免多语言 **duplicate**（`hreflang`、独立 URL、各语言自洽的 title/description）。*线上 hreflang/canonical 现场校对见 §8。* |
| **只为「有多语言」而堆语言** | 性价比通常低；**无检索量、无维护** 的小语种页易成低质集合，反拖站点印象。 |

**与 SEO 的关系**：小语种排名依赖 **该语言的搜索需求 + 本地化内容质量 + hreflang 正确性**，不是「有英文页就一定带动小语种」。

**会议补充**：**核心词** 建议用 **各语种本地化关键词** 并建 **对照表** 流程化；正文可机翻但核心词需人工校对。英语区竞争激烈；小语种已有排名的词，改动时需 **小范围测 + 监控**，避免误伤。

## 4. 发布后多久评估效果？

**没有单一数字**，可按 **改动类型** 划分观察窗口（以下为经验区间，需结合 GSC 展示量）。

| 改动类型 | 建议最短观察期 | 备注 |
|----------|----------------|------|
| Title / description / 小幅正文 | **2–4 周** | 低展示 URL 需更久才有统计意义。 |
| 结构性内容重写、合并/拆分页面 | **4–8 周** | 可能经历波动，看趋势而非单日。 |
| 新页首次收录与初步排名 | **数周至数月** | 新站或低权威域更慢。 |
| 外链、内链架构调整 | **1–3 个月+** | 信号累积与重新抓取需要时间。 |

**原则**：先保证 **样本量**（展示/点击足够再下结论）；同时记录 **发布日与改动日志**，避免把算法波动误读为单次改版效果。

**可选节奏**：在日历上设 **T+14、T+30、T+60、T+90** 四次轻量复盘（索引与抓取可更早看）；**GEO/AI 引用** 若单独监测，勿与 GSC 混为同一套 KPI。

**会议补充**：会上建议以 **1–2 个月** 为 **一轮阶段性观察窗口**；**新页前几周波动大**，约 **1–2 个月后** 相对 **稳定**，稳定后再优化更易看到排名阶跃。可与上表 **合并使用**（大改版偏长、snippet 小改偏短）。

## 5. AI Tools 类页面 vs. Template 页面：优先做谁？

**若只能二选一，默认优先顺序**：

1. **更贴近商业意图与转化的类型**（通常 **Use case / 解决方案 / 与产品强相关的模板** 优于泛「AI tools 列表」——除非你们明确以列表页做流量入口）。
2. **Template 页** 往往在 **长尾、程序化扩展、内链枢纽** 上更可持续；**AI tools** 类词竞争大、同质化高，需极强差异化或数据才能站稳。

**实操**：用 **关键词难度 + 与 Kuse 功能的一一对应** 打分；优先做 **能自然接到注册/demo 路径** 的模板或场景页，工具聚合页可作为 **支撑话题** 而非唯一重心。

**若两簇同时推进资源紧**：可先 **选一条垂直**（例如与 `/excel`、表格、演示强相关的模板或工具主题）**打穿** 再扩簇，避免两簇同时薄内容上线。

**会议补充（Kuse 站）**：

| 类型 | 观察 |
|------|------|
| **AI Tools 系列** | 约 **3 月初** 上线一批；**流量相对更好**，部分词 **7–9 位**。 |
| **Templates 落地页** | 约 **1 月底–2 月** 上线；整体 **弱于 AI Tools**，多数字 **排名靠后**；与 **Canva 等** 同场竞争，模板路径偏曲折。可借鉴 **长尾先行**（长尾单量低但可积权重，再 **内链** 汇向核心页）；亦可参考同类 **Mirror** 等产品打法。 |

## 6. 外链：主页新闻稿 vs. 子页论坛外链慢收录

**是否继续论坛/子页外链？**  
**可做，但定位为补充**，且重视 **相关性、自然锚文本、页面可被索引**。若收录很慢：检查 **页面是否可被爬、是否 noindex、是否重复内容**；论坛帖常因 **低质模板、无内链、无更新** 而收录慢。

**外链是不是已有页面排名的「核心原因」？**  
**不总是**。对竞争度高的词，外链常是 **重要因素之一**；但对许多页面，**意图匹配、内容质量、内链、用户体验、技术可索引** 会先成为瓶颈。**「主页强、子页弱」** 很常见：品牌与根域权威集中在首页，**子页仍需自己的主题相关外链与内链支撑**。

**建议**：  
- 新闻/媒体链到主页：**品牌与域名信任** 有用。  
- 子页：**优先行业相关、能带推荐流量的来源**；不必与主页二选一，而是 **分层建设**。

**会议补充**：**谨慎购买**；guest post 等看 **竞争度、人力与预算**。类型上优先 **竞品/同类站、个人博客、垂类论坛**；对 **Pinterest、Medium 等偏平台型** 的链，会上认为对 **自身权重帮助常有限**，不宜当主策略。**大批量工具/服务商** 若收录差，需 **筛站** 而非堆量。

## 7. 内链：早期不重视时，最基本逻辑是什么？

**目标**：让 **重要页面** 在站内 **可发现、可理解主题层级、可传递权重**，并减少孤立页。

**基本规则（可立即执行）**：

| 规则 | 说明 |
|------|------|
| **枢纽页（Hub）** | 每个核心主题一个汇总页（如某条产品线、某类模板），从导航或父级页链入。 |
| **上下文链接** | 正文中用 **描述性锚文本** 链向相关深度页，而非全站只链「首页」「联系我们」。 |
| **深度控制** | 重要着陆页尽量 **≤3 次点击** 从首页到达（理想情况）。 |
| **避免** | 全站侧栏同一组「关键词堆砌链接」、或大量重复页脚链接（易显操纵感）。 |
| **新页上线清单** | 新 URL **至少被 1–3 篇相关旧页** 指向；同时考虑 **面包屑**（若站点结构支持）。 |

**与外链的关系**：内链是 **可控、低成本** 的站内信号；先把 **高价值页互相织网**，再谈外链放大。

**会议补充**：**增加入口**（Banner、导航、重要页）为目标 URL 曝光。两种目的：① **相关性 + 用户意图** → 链向 **功能相关** 页；② **硬推新功能** → 可加链但 **转化未必好**。做法：**人工** 维护；或 **AI 按规则批量**（需与页面/站点对齐的 **Excel 上下文表**）；或用 Google **`site:` + 关键词** 找站内页再手动加（**慢**）。可先 **人工做示例** 再让 AI 学规则。内链优先级可结合 **模板长尾、关键词排名与搜索量**。

## 8. Canonical 与 hreflang（现场校对 · Kuse 站）

**背景**：**kuse.ai** 站内反馈 canonical、`hreflang` 配置存在问题。下表为 **2026-03-31** 通过 `curl` 拉取公开 HTML（`User-Agent: Mozilla`）检视 `<head>` 的校对摘要；**以线上实际输出为准**，部署变更后需复测。**Junior** 若独立建站，需 **单独排查**，不在下表范围。

### 8.1 校对范围

| URL | 说明 |
|-----|------|
| `https://www.kuse.ai/` | 首页 |
| `https://www.kuse.ai/kuse` | 英文产品页（与首页同套模板） |
| `https://www.kuse.ai/excel` | Kuse for Excel |
| `https://www.kuse.ai/faqs` | FAQs |

### 8.2 发现

| 项目 | 现象 | 风险 / 说明 |
|------|------|-------------|
| **首页 `/` 与 `/kuse` 的 hreflang** | 多个 `link rel="alternate"` 的 `hreflang`（含 `x-default`、`en`、`ja`、`ko`、`it`、`pt`、`zh`、`zh-TW`）**全部指向同一 URL**：`https://kuse.ai` | **严重**：各语言应对应 **独立 URL**（与语言切换器中的 `/ja/kuse`、`/zh-cn/kuse` 等一致）。当前实现等于向搜索引擎声明「多语言版本是同一页面」，与站内实际多路径 **不一致**，易导致 hreflang 无效或错误聚合。 |
| **Canonical（首页类）** | `link rel="canonical"` 为 `https://kuse.ai`（无 `www`、无路径） | **需注意**：与 `www.kuse.ai` 访问并存时，应用 **301 + 单一规范主机**（www 或 apex）统一；若 `/` 与 `/kuse` 内容高度重复，需明确 **每个 URL 的 canonical 目标**（通常选一主 URL，避免双索引）。 |
| **`/excel` 的 canonical** | 在完整 HTML 中 **未检出** `rel="canonical"` | **中高**：子页缺少 canonical 时，易在参数、追踪、`www`/非 `www` 并存下出现 **重复 URL**；建议每页输出 **自引用绝对 URL** canonical。 |
| **`/excel`、`/faqs` 的 hreflang** | `alternate` 的 `href` 为 **相对路径**（如 `/excel`、`/ja/excel`、`/zh-cn/excel`） | **中**：Google 文档建议 hreflang 使用 **绝对 URL**（含 scheme 与主机），减少解析歧义；且须与 **实际可访问的规范域名**（`www` vs apex）一致。 |
| **属性写法** | 输出中为 `hrefLang`（驼峰） | 一般可被解析；建议统一为 **`hreflang`**（小写）以符合常见示例与校验工具习惯。 |
| **Meta 描述** | 首页 meta description 中可见编码异常片段（如 `websites??eady`） | 与 hreflang 无关，但影响摘要质量，建议一并修复文案编码。 |

### 8.3 建议修复顺序（执行侧）

1. **修正首页级 hreflang 映射**：每个 `hreflang` 指向 **该语言的真实绝对 URL**（与 Webflow/站点语言子路径一致），并保证 **互链成组、双向一致**（每语种子页也返回同组 `alternate`）。
2. **全站补 canonical**：至少为 `/excel`、`/faqs` 及主要着陆页输出 **绝对路径 canonical**；与 **301 规范主机** 策略对齐。
3. **hreflang 绝对化**：将 `/excel`、`/faqs` 等页的 `href` 改为 `https://www.kuse.ai/...`（或与最终选定规范主机一致）。
4. **复测**：用 [Google Search Console URL 检查](https://search.google.com/search-console)、Rich Results Test / 第三方 hreflang 校验工具对抽样 URL 复验。

## 9. 会议纪要：Kuse 与 Junior（双产品对齐）

**Junior** 执行项在文末行动清单中单独标注。

### 9.1 产品分工与规模（会议口径）

| 维度 | Kuse（kuse.ai） | Junior |
|------|-----------------|--------|
| **角色** | SEO 主战场；约 **2024 年 10–11 月** 起系统投入 | 约 **2025 年 3 月中下旬** 推出的 **新品**（同团队） |
| **规模** | 对外约 **近千页**；自动多语言后 **unique 约 100+** | 以实际上线与路由为准 |
| **SEO 三块** | 首页/核心词、子页与落地页、博客 | 单独排期与关键词地图 |

### 9.2 主要问题（共识 · 偏 Kuse 站）

| 问题 | 说明 |
|------|------|
| **定位偏模糊** | 首页与核心词表达偏谨慎，泛词（如 *AI workspace*）需收紧为 **可落地的功能与场景**（与 [kuse.md](./kuse.md) 定位对齐）。**文案与能力一致**：产品为 **Copilot / 协作式** 产出路径，**避免**将 Kuse 写成 **Agentic 自主多步执行**（易与真实体验不符、损害信任与转化）。 |
| **内链薄弱** | 权重传递与导航不足；见 **§7** 会议补充。 |
| **博客** | 词与 **产品关联弱**；**URL 层级/路由** 不理想；宜以 SEO 为导向收束到 **`/blog/`** 等统一子路径；Slug 用 **缩略核心词**、**避免年份**；调整可用 **301** 或 **新文承接**。部分流量来自 **AI 推荐**，不宜只按传统 CTR 解读。 |

### 9.3 流量获取与转化（Kuse / Junior / 公司级）

| 方向 | 要点 |
|------|------|
| **老站带新站** | 在老站 **顶部 banner / 公告**、**About**、**页脚** 介绍新产品或新站；**社媒** 同步（渠道以实际为准）。 |
| **UGC / 红人** | 会上背景：**UGC 占流量大头** 时需 **脚本与爆款内容**；**UGC 分享计划**、**推荐/分销**；红人协商 **个人网站外链** 与费用。 |
| **可分享资产** | **Prompt 合集、Skill 分享** 等；**转化路径** 要顺滑（少手动复制、少绕路登录），**预填内容回传** 可降低流失。 |
